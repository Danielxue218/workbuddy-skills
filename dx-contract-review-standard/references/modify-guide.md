# 合同修改文件生成规则 modify-guide.md

> **场景极度垂直 · SOP 极度精简 · 交付极度优雅**
>
> 本文件定义八件套中"合同文本四件"(批注版 / 修订版 / 修订批注版 / 清洁版)的生成规则。
> `generate-modified.py` 脚本按此规则在**原合同 docx 上直接施工**。
>
> 分析四件回答"这份合同有什么问题、怎么谈";文本四件回答"改完的合同长什么样"。

---

## 核心特性(v1.0.0 · 随 skill v2.0.0 首发)

| 特性 | 说明 |
| --- | --- |
| 四种模式 | annotate 批注版 / revise 修订版 / both 修订批注版 / clean 清洁版,一条命令 `--mode all` 全出 |
| 数据零新增 | 完全复用 report-data.json,不需要为文本四件准备额外数据 |
| 署名参数化 | 批注作者与修订作者 = `data["lawyer"]`(经办律师),Word 审阅窗格显示的是使用者的名字 |
| 修订可逐条处理 | 修订版使用标准 OOXML 修订(`w:ins`/`w:del`),Word 中可逐条"接受/拒绝" |
| 缺失条款自动补入 | 修订版/清洁版把 `missing_clauses` 的桥面条款按"第X条"编号补入正文末尾、签章页之前 |
| 定位三层防御 | 精确匹配 → 模糊匹配(阈值 0.80,标注"建议人工核对") → 显式失败清单,绝不静默跳过 |
| 无占位符原则 | 清洁版定位是"可直接签订",桥面条款与修改建议中禁止出现 `[地址]` 等占位符 |

## 一、四版本定位(先读这一节)

| 版本 | 正文是否修改 | 修改是否留痕 | 是否含批注 | 典型用途 |
| --- | --- | --- | --- | --- |
| 批注版 | 否 | — | 是 | 发给委托人/团队,展示"哪里有问题、为什么" |
| 修订版 | 是 | 是(修订模式) | 否 | 发给对方,对方可逐条接受/拒绝 |
| 修订批注版 | 是 | 是(修订模式) | 是 | 内部评审:既看改动,又看改动理由 |
| 清洁版 | 是 | 否 | 否 | 双方达成一致后的定稿,可直接签订 |

**推荐工作流**:批注版(内部沟通)→ 修订批注版(内部定稿评审)→ 修订版(发对方谈判)→ 清洁版(共识落定后出定稿)。

**重要边界**:清洁版是"按本次审查结果单方修改完成"的版本,**不代表对方已同意**。在对方确认前,清洁版仅用于展示目标状态,不得直接用于签署。

## 二、数据契约(与 report-data.json 的字段对应)

文本四件从 report-data.json 读取以下字段,**不需要新的 JSON**:

| 字段 | 使用者 | 要求 |
| --- | --- | --- |
| `lawyer` | 全部四版 | 批注作者、修订作者、文档属性"最后修改者"。必填。 |
| `findings[].original_text` | 批注版锚点 | **必须是合同原文的逐字引用**(标点、空格可有全半角差异,引擎会归一化) |
| `findings[].suggestion_original` | 修订/清洁版被替换文本 | **必须与合同逐字一致**,这是替换的定位依据 |
| `findings[].suggestion_revised` | 修订/清洁版替换文本 | `**...**` 标记会被剥离(该标记仅用于 Word 报告的红字渲染) |
| `findings[].apply_modification` | 修订/清洁版 | 可选,默认 `true`。设为 `false` 表示该 finding 只分析不动文(如需商业判断的条款) |
| `missing_clauses[].bridge_clause` | 修订/清洁版补入 | 将剥离 `**` 后作为新条款正文;**禁止占位符** |
| `extra_findings[].original_text` | 批注版锚点 | 清单外发现只批注、不改文(通常无逐字替换对) |

### 逐字引用铁律(AI 必读)

生成 report-data.json 时,`original_text` 和 `suggestion_original` **必须从合同文本复制,不得凭记忆转写**。
转写("应当"写成"应"、"本合同总金额"写成"合同总金额")会导致修订/清洁版定位失败或落入模糊匹配。
自检方法:生成 JSON 后,逐条在合同文本中搜索 `suggestion_original`,确认能找到。

## 三、各版本生成规则

### 3.1 批注版(annotate)

- 正文一字不动。
- 每条 finding 以 `original_text` 为锚点添加一条 Word 批注,批注文案结构:

```
【■ 高风险 · C025 · L3 · 精准审查】{问题标题}
风险说明:{risk_description}
修改建议:{suggestion_revised 剥离 ** 后}
相关法条:{related_laws}
```

- 清单外发现(`extra_findings`)同样批注,首行标签为 `【清单外发现】`。
- 缺失条款不改正文,在最后一个条款正文上锚一条 `【缺失条款提示】` 汇总批注。
- 批注文案遵守视觉规范:■ 功能符号 + 文字标签,**不使用 emoji**。

### 3.2 修订版(revise)

- 对每条具备 `suggestion_original` / `suggestion_revised` 的 finding:
  原文包裹为 `w:del`(删除线),替换文本包裹为 `w:ins`(插入),作者 = 经办律师,日期 = 审查日期。
- 缺失条款按以下规则补入:
  - 位置:正文最后一个"第X条"之后、签章页标记("以下无正文"等)之前
  - 编号:自动识别现有最大条号 +1(中文数字,如"第十六条"),正文按 "16.1" 小节编号
  - 段落格式:克隆现有条款标题段/正文段的格式
  - 整段标记为修订插入(含段落标记),对方拒绝修订时可整段还原
- 不添加任何批注。

### 3.3 修订批注版(both)

- 修订规则同 3.2。
- 每处修订的**插入文本**上锚一条批注(文案同 3.1),即"看到改动,旁边就是理由"。
- 清单外发现按 3.1 规则批注。

### 3.4 清洁版(clean)

- 直接以 `suggestion_revised`(剥离 `**`)替换 `suggestion_original`,无任何修改痕迹。
- 缺失条款按 3.2 的位置与编号规则补入,普通文本。
- 不添加批注。整份文档保持原合同的字体与版式。

## 四、定位引擎与失败处理

### 4.1 三层防御

1. **精确匹配**:剥离空白 + 全半角标点归一化后精确查找。
2. **模糊匹配**:difflib 相似度 ≥ 0.80 时按匹配块还原区间,控制台标注 `⚠ 模糊定位(建议人工核对)`。
3. **显式失败**:列入"定位失败清单"并输出到控制台,exit code 2(单模式)。**绝不静默跳过**。

### 4.2 Claude 处理定位失败的标准动作

- 打开原合同,找到该条款的**逐字原文**,修正 report-data.json 对应字段
- 重新运行 `generate-modified.py`
- 如条款确实无法逐字定位(如扫描件转换噪声),向用户说明该条需人工处理,不得假装成功

### 4.3 模糊定位的报告义务

出现模糊定位时,Claude 必须在最终交付说明中列出这些条目,提示律师打开修订版核对定位是否准确。

## 五、执行命令

```bash
# 一次生成四件(推荐,Step 4 默认)
python3 scripts/generate-modified.py \
    --contract "<原合同>.docx" \
    --data "<输出目录>/report-data.json" \
    --mode all \
    --output-dir "<输出目录>" \
    --contract-name "{合同名}"

# 单独生成某一版
python3 scripts/generate-modified.py \
    --contract "<原合同>.docx" --data "report-data.json" \
    --mode revise --output "{合同名}_修订版.docx"
```

**输出扩展名必须是 `.docx`**(脚本会校验)。`--mode all` 输出四个文件:
`{合同名}_批注版.docx` / `{合同名}_修订版.docx` / `{合同名}_修订批注版.docx` / `{合同名}_清洁版.docx`。

**输入约束**:`--contract` 必须是可机读的 `.docx` 原合同。扫描版 PDF 须先 OCR 转换;
转换文本可能引入噪声,此时应预期更多模糊定位并加强人工核对提示。

## 六、质量检查清单

生成文本四件后自检:

### 内容完整性
- [ ] 修订版/清洁版:每条 `apply_modification != false` 且具备替换对的 finding 均已定位处理
- [ ] 缺失条款已按"第X条"编号补入(或已在报告中说明插入失败原因)
- [ ] 批注版:findings + 清单外发现 + 缺失条款提示的批注数量对得上
- [ ] 定位失败清单为空;模糊定位条目已在交付说明中列出

### 技术正确性
- [ ] 修订作者与批注作者 = 经办律师(不是工具作者)
- [ ] 修订版在 Word 中可逐条"接受/拒绝",全部接受后与清洁版正文一致
- [ ] 清洁版无 `**` 残留、无占位符、无风险原文残留

### 法律边界
- [ ] 清洁版交付时已提示"系单方修改稿,对方确认前不得用于签署"
- [ ] 需商业判断的条款已用 `apply_modification: false` 排除,未擅自替用户做商业决定
