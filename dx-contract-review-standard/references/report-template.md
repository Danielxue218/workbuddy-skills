# 合同审查报告模板 report-template.md

> **场景极度垂直 · SOP 极度精简 · 交付极度优雅**
>
> 本文件定义标准审查四件套中"审查报告"的完整结构和格式要求。
> `generate-report.py` 脚本按此模板生成 Word 文档。
>
> 审查报告的核心定位:**逐条对照清单发现风险 + 给出可直接落地的修改建议**。

---

| 特性 | 说明 |
| --- | --- |

## 模板使用说明(先读这一节)

### 一、审查报告在四件套中的位置

本模板属于标准审查 Skill 输出的四件套,各司其职:

| 文件 | 定位 | 性质 | 读者 |
| --- | --- | --- | --- |
| 合同概要 summary | 客观信息提取 | 事实 | 团队成员、委托人、归档 |
| **审查报告 report** | **风险分析与修改建议** | **判断** | **经办律师、决策者** |
| 谈判优先级清单 negotiation | 谈判策略与桥面条款 | 策略 | 谈判桌上的律师 |
| 业务流程图 flowchart | 履约流程可视化 | 图示 | 全体相关人员 |

**审查报告是四件套的核心产出**,其他三份可视为审查报告的辅助文件。

### 二、审查报告的三个核心原则

**原则一:反噪音**

只报告清单(checklist.md)命中的问题和确实存在的缺失条款。不主动"建议补充 XX 条款",除非清单里有对应检查项。不输出"建议完善 XX 机制"等方向性废话。**宁可少报,不可乱报**。

**原则二：最小修改**

修改建议必须给出可直接粘贴替换的具体条款文字。格式统一为：
```
原文："{有问题的原文片段}"
→ 建议修改为："{可直接替换进合同的具体条款文字}"
```
只改有问题的部分，保留合同原文中没问题的部分。

**原则三：可追溯**

报告中的每一条风险发现都能追溯到：
- 合同文本（条款位置 + 原文摘录）
- 审查清单（稳定 ID，如 C021）
- 法律依据（如引用法条，必须规范化标注）

### 三、与审查清单（checklist.md）的对应关系

审查报告中的每一条风险发现都必须标注其对应的审查清单检查项 ID（C001-C060）。读者通过该 ID 可以精确回查：
- 触发此风险的判断标准
- 该检查项的确认层级（L1/L2/L3）
- 行业分化阈值（如有）
- 立场差异说明

## 审查报告完整结构

### 第一章 · 封面

报告封面以 A4 单独一页呈现，不与正文合页。包含以下信息：

```
合同审查报告

Contract Review Report

---

合同名称：{合同全称}
审查编号：MQC-REV-{YYYYMMDD}-{序号三位数}

委托方：{委托方全称}
受托律所：{律所全称}
经办律师：{律师姓名}

审查立场：{甲方立场 / 乙方立场 / 中性立场}
审查依据：标准审查清单 v{版本号}
审查日期：{YYYY 年 MM 月 DD 日}

---

本报告是对 {合同名称} 的审查意见。
所有风险判断基于审查时的合同文本，不含后续变更。
```

**封面设计规范**（包豪斯风格 · 与 generate-report.py 实现一致，权威定义见 `visual-style-guide.md`）：
- 单外层表格布局，保证封面恰好一页；封面不显示页眉页脚
- 顶部主色横带 + 水平细线装饰，主色浅蓝 `#1387C0`
- 大标题"合同审查报告"左对齐，宋体加粗，黑色
- 信息区左对齐：合同名称 / 审查编号 / 委托方 / 经办律师（`lawyer · law_firm`，来自数据 JSON）/ 审查立场 / 审查日期
- 封面底部品牌行：默认 "LEGAL AI TOOLMAKER · 法律工具制造者 | 缪奇川律师 出品"，可用数据 JSON 的 `brand_line` 字段整体替换，设为空字符串则不显示（v2.0 起）

### 第三章 · 执行摘要

```
二、执行摘要
```

本章以**一页篇幅**呈现报告的核心结论，便于决策者快速了解。

#### 3.1 综合风险评级

**评级：{■ 高风险 / ■ 中风险 / ■ 低风险}**

**评级规则**：
- 存在任何 ■ 高风险项 → 综合评级为 ■ 高风险
- 无 ■ 高风险 但存在 3 个及以上 ■ 中风险 → 综合评级为 ■ 中风险
- 无 ■ 高风险 且 ■ 中风险 少于 3 个 → 综合评级为 ■ 低风险

#### 3.2 可签性判断

**判断：{■ 低风险 · 建议签约 / ■ 中风险 · 修改后签约 / ■ 高风险 · 不建议签约}**

**判断规则**：
- ■ **建议签约**：无 ■ 高风险项；■ 中风险 项数量可控且均非核心条款
- ■ **修改后签约**：存在 ■ 高风险 但可通过谈判修改；或 ■ 中风险 项涉及核心条款
- ■ **不建议签约**：存在不可修改的 ■ 高风险项（如违反强制性规定）；或谈判空间极小

#### 3.3 审查结论摘要

一段话，不超过 300 字：
- 点明合同的核心交易结构
- 指出最核心的 1-3 个问题
- 给出"可签/修改后签/不建议签"的明确建议
- 说明修改的优先事项和大致方向

**示例**：
> 本合同为 {交易结构一句话概述}。审查发现 ■ 高风险 {X} 处、■ 中风险 {Y} 处、■ 低风险 {Z} 处，综合评级 ■ 中风险，建议修改后签约。核心问题集中在：(1) {问题一}；(2) {问题二}；(3) {问题三}。其中 {问题一} 涉及合同核心权利义务，必须优先协商；{问题二} 建议对方提供相应保障条款后可接受；{问题三} 为格式瑕疵，修改难度小。具体修改建议详见第五章。

#### 3.4 优先处理事项（Top 3）

按处理紧迫性和谈判必要性列出必须最先处理的 3 项：

| 序号 | 问题 | 风险等级 | 对应清单 | 建议行动 |
| --- | --- | --- | --- | --- |
| 1 | {问题概述} | ■ 高 | C025 连带责任 | 立即与对方协商，无法谈判则不签 |
| 2 | {问题概述} | ■ 高 | C038 诉讼仲裁并存 | 必须二选一，不可同时约定 |
| 3 | {问题概述} | ■ 中 | C021 违约金比例 | 建议调整至行业合理区间（10%-20%） |

### 第五章 · 逐条审查详情

```
四、逐条审查详情
```

每条风险发现按以下结构展开(使用**三列对照表**呈现核心的"原文 vs 建议 vs 理由"):

```
风险 {序号}   ■ {高/中/低}风险   [精准审查]   {问题标题}

条款位置:第 X 条第 X 款  ·  对应清单:{C021}  ·  确认层级:{L2}  ·  规则来源:{标准清单 / Playbook 覆盖 / 清单外发现}  ·  谈判优先级:{Tier 1/2/3}

触发标准:{引用清单中的数字化判断标准,如"违约金超过合同总金额 30%"}
立场判断:{本次审查的立场下,该发现的风险方向}

┌────────────────────┬────────────────────┐
│  条款原文            │  修改建议            │
├────────────────────┼────────────────────┤
│ "...35% 的违约金"   │ "...**15%** 的..."  │  ← **包裹的字为红色 #EE0000
├────────────────────┴────────────────────┤
│  修改理由                                 │
├───────────────────────────────────────── ┤
│  {这个问题在实务中意味着什么,建议为何是合理折中} │
└──────────────────────────────────────────┘

相关法条:{参见本报告第七章"法条引用索引"。此处列出条文速引,如"民法典 §585"}
```

#### 字段填写规范

**条款位置**:精确到条、款、项。多条款联动时列出全部涉及条款(如"第 8.3 条、第 12.1 条")。

**对应清单**:严格使用 checklist.md 中的稳定 ID(C001-C060),不用"5.1 违约金比例"这样的层级编号。

**确认层级**:从 checklist.md 继承。L3 项在审查报告的页眉或页脚显示"含 L3 项,建议人工逐条复核"提示。

**规则来源**:三选一
- `checklist` · 命中标准清单(通用律师共识)
- `playbook` · 命中组织立场手册(覆盖了 checklist 的默认判断)
- `extra` · 清单外发现(不属于前两类,AI 自主识别)

**精准审查**:对 L3 级别、Tier 1 级别、核心商业条款,在 JSON 中标注 `"is_precise_review": true`,输出 Word 里显示 `[精准审查]` 文字标签(律师文件**不使用 emoji 符号**)。

**合同原文**:填到三列对照表的左列。必须加引号(中文引号),不超过两行。超长条款用省略号截取关键部分。

**修改建议**:填到三列对照表的右列。用 `**改动字**` 包裹要强调的改动部分,生成 Word 时会自动渲染为 `#EE0000` 正红色:
- ■ 高风险和 ■ 中风险项必须给出具体的桥面条款文字
- ■ 低风险项可给出方向性建议
- 涉及商业判断的条款(如价格、期限等商业条件),明确标注"需律师根据交易背景判断"

**修改理由**:填到三列对照表的跨列底部行。禁止使用"可能""或许""大概"等模糊词。说明实际后果,不做推测。一段话,不超过 150 字。

**相关法条**:表格外独立行,使用速引格式,详细条文引用汇总在第七章。

**谈判优先级**:直接映射风险等级到 Tier 等级(■ 高 → Tier 1;■ 中 → Tier 2;■ 低 → Tier 3)。

### 第六章 · 缺失条款提示

```
五、缺失条款提示
```

**本章机制说明**:

> 本章列出审查清单中标记为"缺失检查项"(`is_completion_check=true`)、但合同文本未发现对应条款的项目。清单外条款不在此章列出(清单外条款归入第六章"清单外发现")。
>
> 这一设计的目的是让读者明确:**报告里的"缺失"是相对于 checklist 的定义而言的缺失,而不是 AI 基于自由判断的"应该补充"**。避免"AI 什么条款都觉得应该加"的无边界噪音。

列出审查清单中要求审查但合同中未出现的条款:

| 序号 | 缺失条款 | 对应清单 | 重要程度 | 建议 |
| --- | --- | --- | --- | --- |
| 1 | 争议解决条款 | C037 | ■ 必须补充 | 建议约定甲方所在地人民法院管辖 |
| 2 | 不可抗力条款 | C046 | ■ 建议补充 | 建议增加标准不可抗力条款(详见下方桥面条款) |
| 3 | 数据保护协议 | C059 | ■ 必须补充 | 本合同涉及个人信息处理,必须签订 DPA 作为附件 |

**对每一项"必须补充"和"建议补充"的缺失条款,提供可直接使用的桥面条款**(使用三列对照表呈现,左列固定为"(合同中未约定此条款)",右列为桥面条款文本,底部跨列为"补充理由"):

```
【缺失 1】争议解决条款（C037）

建议条款：
因本合同产生的或与本合同有关的任何争议，双方应通过友好协商解决；协商不成的，任何一方均有权向 {甲方所在地城市} 人民法院提起诉讼。本合同适用中华人民共和国法律。
```

### 第七章 · 清单外发现

```
六、清单外发现
```

审查过程中发现的、当前审查清单未覆盖但值得关注的问题。每条标注建议补充到清单的哪个维度：

```
【清单外发现 1】{问题描述}

▎条款位置：{}
▎合同原文：{摘录}
▎问题分析：{一段话说明}
▎建议处理：{如何处理此问题}
▎建议补充到清单：{维度名称，如"五、违约责任"}
```

**说明**：清单外发现是 checklist.md 持续迭代的核心输入。每次审查后，作者应考虑是否将此类发现正式补入清单。

### 第八章 · 法条引用索引

```
七、法条引用索引
```

本章集中列出报告中引用的全部法律法规和条文。**每一条引用必须规范化标注**：

#### 8.1 引用规范

每条法条引用包含五项要素：

1. **法规全称**：如"《中华人民共和国民法典》"
2. **现行版本年份**：如"（2020 年制定，2021 年 1 月 1 日施行）"
3. **条文编号和款项号**：如"第 585 条第 2 款"
4. **条文原文引用**：不超过 50 字，用引号标注
5. **本报告校验日期**：如"2026 年 4 月 17 日"

**引用格式示例**：
```
【1】《中华人民共和国民法典》（2020 年制定，2021 年 1 月 1 日施行）第 585 条第 2 款

原文："约定的违约金过分高于造成的损失的，人民法院或者仲裁机构可以根据当事人的请求予以适当减少。"

引用于：风险 3（违约金比例超标）
校验日期：2026 年 4 月 17 日
```

#### 8.2 引用汇总

```
《中华人民共和国民法典》
- 第 180 条（不可抗力）：引用于缺失 2
- 第 498 条（格式条款解释规则）：引用于风险 5
- 第 585 条（违约金调整）：引用于风险 3

《中华人民共和国仲裁法》
- 第 16 条、第 17 条（仲裁协议效力）：引用于风险 8

《中华人民共和国民事诉讼法》
- 第 24 条（合同纠纷管辖）：引用于缺失 1
- 第 90 条（送达地址）：引用于风险 10

《中华人民共和国个人信息保护法》
- 第 23 条（提供个人信息）：引用于缺失 3
```

#### 8.3 法条不确定的处理

**绝不编造不存在的法条**。宁可不引用，不可虚假引用。

**1. AI 辅助性质**

本审查报告由 AI 工具辅助生成，基于作者定义的审查清单逐条审查。所有风险分析和修改建议仅供参考，**必须由执业律师审核确认后方可作为法律意见使用**。本报告不构成法律意见书。

**2. 审查时效性**

本报告基于审查日期时的合同文本及当时有效的法律法规。合同文本如有变更（包括附件、补充协议、口头补充约定），需重新审查。法律法规后续变动可能影响本报告的部分结论。

**3. 审查范围限制**

本报告仅限于对合同文本本身的审查，不包括：
- 合同主体的工商登记、资质、经营状况等外部核查（请调用 mqc-entity-verify 或类似 Skill）
- 合同背景事实的真实性核实
- 合同商业条件的合理性评估（如价格是否合理、交付时间是否激进）
- 合同履行中的实际风险（如对方履约能力、市场变化）

**4. 清单覆盖边界**

本报告基于审查清单 v1.0.0 逐条审查。清单未覆盖的风险可能未被发现。如发现清单外风险，已在"清单外发现"章节列出。审查清单后续迭代不溯及本报告。

**5. 法条引用说明**

本报告引用的法条已尽力核验，但 AI 工具对法条的记忆可能存在偏差。所有法条引用以该法律的官方发布版本为准。标注"⚠️ 待核实"的法条请律师特别复核。

**6. 使用范围限制**

本报告仅供本次审查的委托方及其指定人员使用，未经作者书面同意，不得对外披露、转载或用于除审查委托目的之外的其他用途。

**7. 律师独立判断**

本报告的任何结论和建议不替代执业律师在具体案件中的独立判断。律师应根据本次交易的具体背景、当事人的商业诉求、过往交易习惯等综合判断。

**8. 合同文本完整性说明**

如合同文本中包含 AI 无法识别的信息（如手写批注、图片签章、扫描页面的模糊文字），可能影响本报告的完整性。审查前应尽量使用可机读的电子版合同文本。

## 格式要求

### 文档规范

- **字体**（与 `_common.py` 实现一致）：
  - 正文：宋体（小四，12pt），首行缩进 0.85cm，两端对齐
  - 标题一级：宋体加粗（16pt），应用 Word 内建 Heading 1 样式（导航窗格可见），黑色
  - 标题二级：宋体加粗（14pt），应用 Word 内建 Heading 2 样式，黑色
- **行距**：1.5 倍行距
- **页边距**：上下 2.54cm，左右 3.17cm（Word 默认 A4）
- **页眉**：`{合同名称} · 合同审查报告`
- **页脚**：
  - 左：`审查编号：MQC-REV-{YYYYMMDD}-{序号}`
  - 右：`第 X 页 / 共 Y 页`
- **封面**：单独一页，不显示页眉页脚

### 颜色规范

以 `visual-style-guide.md` 为**唯一权威来源**。核心原则：**全局黑字**——除以下功能性着色外，整份报告（含标题）统一黑色。

| 元素 | 色值 | 说明 |
| --- | --- | --- |
| ■ 高风险符号 | `#FF0000` | 正红（仅 ■ 方块着色，"高风险"文字标签为黑色） |
| ■ 中风险符号 | `#FF9900` | 标准橙（仅 ■ 方块着色） |
| ■ 低风险符号 | `#00A650` | 正绿（仅 ■ 方块着色） |
| ✓ 正常 | 不着色 | 黑色文字 |
| 三列对照表"建议"列中 `**...**` 改动字 | `#EE0000` | 正红（Word 修订工作习惯，仅改动的字着色，其余黑色） |
| 桥面条款"建议修改为"/ 缺失条款桥面建议 | `#0070C0` | 专业蓝（Office 标准色，律师惯用） |
| [待核实] 文字标注 | `#FF9900` | 标准橙，与中风险符号同色 |

**符号规范**：风险等级一律使用 **■ 方块（U+25A0）+ 文字颜色染色 + 黑色文字标签**，不使用 emoji 圆球。

**不使用的颜色**：
- 不使用纯黄 `#FFFF00`（白底不可见）、荧光绿 `#00FF00`（视觉刺激）
- 不使用琥珀黄 `#FFC107`（已被标准橙 `#FF9900` 取代，见 visual-style-guide 迭代记录）
- 不使用深红 `#C00000` 或金色 `#E8A500`（作者个人品牌色，仅在课件等品牌物料使用）

### 篇幅控制

- 简单合同（15 页以内）：审查报告 8-12 页
- 中等合同（15-30 页）：审查报告 12-20 页
- 复杂合同（30 页以上）：审查报告 20-35 页
- 极复杂合同（投资协议、并购协议等）：审查报告可超过 35 页，但执行摘要仍须控制在 1 页内

### 封面设计

包豪斯风格，完整规范见 `visual-style-guide.md` 的封面章节，与 `generate-report.py` 实现一致：

- 单外层表格布局保证单页；主色浅蓝 `#1387C0` 横带 + 细线装饰
- 标题"合同审查报告"宋体加粗、左对齐、黑色；英文副标题 Times New Roman
- 信息区左对齐（含"经办律师"行，取数据 JSON 的 `lawyer` / `law_firm` 字段）
- 底部品牌行可配置（`brand_line` 字段，v2.0 起）
