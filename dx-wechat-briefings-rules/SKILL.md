# M17 法律朋友圈卡片生成铁律（v7.2）

## 一、两条不可违背的硬规则

### 规则 1：三天内主题/案由/关键词禁止重复

- **范围**：最近 3 个自然日（含当天之前 3 天）已生成的 `m17.cases[*].title` 与 `m17.cases[*].kicker`。
- **实施位置**：`m17_compressor.py::_get_recent_titles(base_dir, today_str)`
- **行为**：
  1. 自动读取 `{BASE}/briefings/{YYYY-MM-DD}-full.json` 中最近 3 天的 `m17.cases`。
  2. 提取所有历史卡片的 `title` 与 `kicker`，按天分组注入 Gemini prompt。
  3. prompt 中明确列出历史标题，要求 Gemini "严禁重复以下主题、案由或关键词"。
  4. 若历史卡片中已出现「特许经营合同」「拒执罪」「一带一路」等主题，今日禁止再次使用同类角度。
- **示例**：2026-07-22 已生成「特许经营合同纠纷裁判风险提示」，则 07-23 至 07-25 期间禁止再出「特许经营合同」相关卡片。

### 规则 2：每天 8 张卡片必须覆盖 8 个不同案由领域

- **实施位置**：`m17_builder.py::_select_articles()` 与 `m17_compressor.py::_build_prompt()`
- **参数**：`MAX_PER_DIR = 1`
- **行为**：
  1. `_select_articles` 先按 10 大案由每类选 1 篇；后续补位时每类最多 1 篇。
  2. 若当天文章无法覆盖 8 个不同案由，则**宁可少出，绝不凑数**。
  3. Gemini prompt 中明确要求："8 张卡片必须来自 8 个不同的 CASE_CATEGORIES，任何两张卡片不得属于同一案由"。
  4. compressor 输出后由 `_dedup_categories()` 校验；若发现同案由重复，丢弃低分者并尝试用其他案由替换。

## 二、10 大民商事案由（CASE_CATEGORIES）

1. 合同纠纷
2. 物权与侵权纠纷
3. 公司与股权纠纷
4. 劳动与人事争议
5. 婚姻家事与继承
6. 金融与保险纠纷
7. 建设工程纠纷
8. 知识产权纠纷
9. 执行与保全
10. 仲裁与调解

## 三、优先劣后（内容选择优先级）

**优先**（按优先级降序）：
1. 各地高院、中院公众号发布的「类案裁判规则」「裁判要旨」「审判要点」
2. 仲裁委员会发布的「典型案例」「裁决规则」「争议解决指引」
3. 法院「审判白皮书」中提炼出的裁判观点（禁止写成「某法院发布白皮书」新闻体）

**劣后 / 剔除**：
1. 检察院来源（已从白名单移除）
2. 工作会议、调研、表彰、党建、培训等活动类文章
3. 仅标题含「发布」「修订」「白皮书」「召开」「签约」而无具体裁判观点的新闻动态
4. 三天内已出现过的主题或案由
5. 当天会导致 8 张卡片出现同案由重复的文章

## 四、朋友圈发文文案（v7.2 新增）

每张 M17 卡片生成后，必须自动生成一条朋友圈发文文案。

- **实施位置**：`m17_compressor.py::generate_moments_copy(cases, today_str)` + `daily_pipeline.py` STEP 2/3
- **输出文件**：`{BASE}/朋友圈发文/YYYY-MM-DD/moments-copy.txt`
- **格式模板**：
  ```
  今日法律观察（M月D日）：{kicker1}·{kicker2}·{kicker3}·...——来自{location1}、{location2}等地法院的民商事裁判动态。
  ```
- **字段规则**：
  1. `kicker` 取自当天卡片 `m17.cases[*].kicker`，去重后按卡片顺序用 `·` 连接。
  2. `location` 通过 `_SOURCE_LOCATIONS` 映射表把来源账号（如"上海高院"→"上海"、"南京中院"→"南京"）转短地名，去重后取前 4 个，用 `、` 连接，后缀"等地法院"。
  3. 若来源不足 4 个，按实际数量输出（如"来自北京法院"）。
  4. 仲裁机构按实际所在地或机构简称输出（如"上海国际仲裁中心"→"上海"，"香港国际仲裁中心"→"香港"）。
- **示例**：
  ```
  今日法律观察（7月23日）：合同纠纷·金融保险·知识产权·执行保全——来自上海、辽宁、杭州、南京等地法院的民商事裁判动态。
  ```
- **禁止**：不要暴露具体案件标题、不要写成营销广告体、不要出现"请点击"/"了解更多"/"免费咨询"等转化话术。

## 五、失败兜底

- **文章不足 8 个不同案由**：输出实际可生成的数量（如 5 张），绝不拿重复领域或新闻动态凑数。
- **Gemini API 失败**：启用 Python fallback，但仍遵守 `MAX_PER_DIR=1`，输出不同案由的卡片。
- **朋友圈文案缺失**：若文案生成失败，pipeline 仍继续输出卡片，但需在 summary 中标记 `moments_copy=MISSING`。
