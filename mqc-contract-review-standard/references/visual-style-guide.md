## 核心规则(v1.0.0)

本节汇总整套视觉规范的关键决策。**所有可视化输出(Word 文档、SVG、流程图)必须遵守**。

### 规则一 · Word 正文严格对齐图书《参考格式》

| 属性 | 规则 |
| --- | --- |
| 一级标题 | 宋体三号(16pt) · 黑色加粗 · 1.5 倍行距 · 段前 16pt 段后 8pt · 首缩 0.85cm · 两端对齐 |
| 二级标题 | 宋体四号(14pt) · 黑色加粗 · 1.5 倍行距 · 段前段后 8pt · 首缩 0.85cm · 两端对齐 |
| 正文 | 宋体小四(12pt) · 黑色 · 1.5 倍行距 · 段前段后 0 · 首缩 0.85cm · 两端对齐 |
| 数字与英文字体 | 全局 Times New Roman |
| Word 样式 | 一级/二级标题必须应用内建 `Heading 1` / `Heading 2` 样式(导航窗格可见) |

### 规则二 · 颜色体系极简

| 使用场景 | 颜色 |
| --- | --- |
| 正文字体 | 黑色 #000000 |
| 一级标题 | 黑色(不用蓝色) |
| 二级标题 | 黑色 |
| 元数据行 | 黑色 |
| 风险 ■ 方块 | 红/橙/绿功能色(唯一保留功能色的地方) |
| 修改建议的改动字 | 正红 #EE0000 · 仅用于 `suggestion_revised` 字段内 `**...**` 包裹的部分 |

**规则**:除风险等级 ■ 符号(红/橙/绿功能色)和修改建议改动字(#EE0000 正红)之外,整份 Word 文档统一黑色。

### 规则三 · 风险卡片采用"三列对照表"结构

核心的"原文 vs 修改建议 vs 修改理由"用**三列对照表**呈现,替代传统堆叠段落:

```
┌────────────────────┬────────────────────┐
│  条款原文(表头)     │  修改建议(表头)     │  ← 第 1 行:浅灰表头,黑字加粗,垂直居中
├────────────────────┼────────────────────┤
│  原文内容           │  建议内容(含红字)    │  ← 第 2 行:数据,垂直居中,左对齐,两列等宽
├────────────────────┴────────────────────┤
│  修改理由 / 补充理由 / 谈判话术(表头)     │  ← 第 3 行:跨列表头
├───────────────────────────────────────── ┤
│  理由内容(跨列)                          │  ← 第 4 行:数据,跨列,左对齐
└──────────────────────────────────────────┘
```

**参数**:
- 列宽:两列各 7.5cm(等宽)
- 表头底色:浅灰 #F1F5F9
- 边框:全 0.5pt 中灰 #BFBFBF
- 单元格垂直居中、段前段后对称、无首行缩进
- 修改建议列内 `**...**` 包裹的文字自动渲染为 `#EE0000` 正红

**三种场景复用同一表格结构**,仅第 3 行表头不同:
- 审查报告风险卡片:"修改理由"
- 缺失条款补充:"补充理由"
- 谈判清单条目:"谈判话术"

### 规则四 · 封面采用包豪斯高端杂志风格

**核心原则**:
- 左对齐强网格(而非居中) —— 包豪斯核心原则
- 色彩极简:浅蓝 **#1387C0** 单色 + 黑字
- 英文大字(36pt 宋体加粗)+ 中文标题(22pt 宋体加粗)形成字重张力
- 细节:顶部 3pt 小色块 + 2pt 短横线 + 1pt 长分隔线 + 极简信息表
- **单外层表格承载所有元素**保证单页不溢出
- 线条用 OOXML `trHeight exact` 精确控制高度,避免字号撑开色块

**参数**:

| 元素 | 属性 |
| --- | --- |
| 顶部小色块 | 2.5cm × 3pt · #1387C0 |
| 英文大字 | CONTRACT / REVIEW / REPORT 等 · 36pt 宋体加粗 · 黑色 |
| 短横线 | 2.5cm × 2pt · #1387C0 |
| 中文标题 | 22pt 宋体加粗 · 黑色 |
| 长分隔线 | 14cm × 1pt · #1387C0(上下各一条) |
| 信息表 | 两列(标签 3.2cm + 值 11cm) · 黑字 · 无边框 · 左对齐 |
| 底部品牌 | `LEGAL AI TOOLMAKER · 法律工具制造者 \| 缪奇川律师 出品` · 9pt 黑字 |

### 规则五 · 三条反噪音机制落地

本 skill 采用三条机制避免 AI 合同审查常见的无边界噪音问题,在视觉上体现:

1. **规则来源标注**:每条风险在元数据行显示 `规则来源:标准清单 / Playbook 覆盖 / 清单外发现`,汇总表单独列"来源"列,报告第 3.3 节给出分布统计
2. **精准审查文字标签**:关键条款标注 `[精准审查]`(不使用 emoji,律师文件不要情绪化符号),汇总表里同一条显示 `[精准]` 前缀
3. **缺失条款机制说明**:报告第五章开头加说明文字"本章列出审查清单中标记为缺失检查项(is_completion_check=true)、但合同文本未发现对应条款的项目"

### 规则六 · 表格样式统一 API

所有表格通过三个函数保证一致性:

- `setup_table_cell_paragraph(para, align, space_pt)`:强制 `Cm(0)` 首缩 + 段前段后对称 + 1.15 倍行距
- `enforce_cell_formatting(table, space_pt)`:一键给整张表的每个单元格应用以上规则 + 垂直居中
- `add_comparison_table(doc, original, revised, reason, label)`:生成三列对照表(含 `**...**` 红字解析)

## 一、设计哲学（先读这一节）

### 1.1 "交付极度优雅"的三个落点

| 维度 | 具体含义 |
| --- | --- |
| **视觉专业** | 输出物看起来像咨询公司的交付物，不像学生作业 |
| **信息层级** | 读者一眼就能识别什么重要、什么次要、什么是注释 |
| **阅读友好** | 留白合理、对齐严格、字号统一，不让读者感到疲劳 |

### 1.2 三个核心原则

**原则一：扁平化**
不使用阴影、渐变、3D 效果、纹理。纯色填充、实线边框（虚线仅用于表达循环或异常路径语义）。视觉元素只用"形状 + 颜色 + 文字"三要素表达信息。

**原则二：简约**
每个视觉元素都有明确功能。装饰性元素一律删除。图表不加无意义的图标，节点不加无意义的装饰。

**原则三：商务感**
配色克制、字体规整、布局严格对齐。避免任何"设计过度"的观感。参考标准是 Linear、Notion、Figma、Stripe、Vercel 等现代 SaaS 产品的视觉气质；色彩饱和度与层级参考 Bloomberg、Goldman Sachs、Morgan Stanley 等金融机构官网的商务基调。

### 1.3 最重要的一条：不是"好看"而是"得体"

**视觉设计的目的不是炫技，是让信息传达最有效**。宁可朴素得体，不可花哨失准。

## 二、色彩系统

这是整份规范最重要的一节。色彩的误用是最容易破坏专业感的地方。

### 2.1 功能色与美学色的严格区分

本 Skill 的色彩系统分为**两层**，不可混用：

| 色彩层级 | 用途 | 色板 |
| --- | --- | --- |
| **功能色** | 传达信息状态（风险等级、成功失败、警示） | 交通灯色系（正红 / 琥珀黄 / 正绿） |
| **美学色** | 视觉呈现（流程图节点、表格、图表、装饰元素、连线、标签） | 商务扁平色系（blue / teal / amber / rose / slate） |

**核心规则**：
- 功能色**只用于**标注状态（风险等级 ■ 高/中/低、确认层级、Tier 分档）
- 美学色**禁止**用在状态标注上（不能用高端蓝表示"低风险"）
- 同一个视觉元素不能同时使用功能色和美学色（避免信息混乱）

**举例**：
- ✓ 流程图的"甲方节点"用**美学色高端蓝**
- ✓ 审查报告的"■ 高风险"用**功能色正红**
- ✗ 流程图的"高风险节点"用**功能色正红** → 违规，这是美学色的领地
- ✗ 风险等级用**美学色**标注 → 违规，失去风险标注的强识别性

### 2.2 功能色色板

仅在涉及**状态标注**时使用，全 Skill 统一。

| 色值 | 名称 | 用途 |
| --- | --- | --- |
| `#FF0000` | 正红 | ■ 高风险 / Tier 1 必须回绝 / 桥面条款原文 |
| `#FF9900` | 标准橙 | ■ 中风险 / Tier 2 建议协商 / [待核实] |
| `#00A650` | 正绿 | ■ 低风险 / Tier 3 可以接受 |
| `#0070C0` | 专业蓝 | 桥面条款建议修改为 / 缺失条款桥面建议 / 清单外发现建议补充 |
| `#000000` | 黑 | ✓ 正常 / 默认文字 |

**色值设计说明**：
- 中档选用 `#FF9900` 标准橙（明亮可读、与红/绿三档对比均衡;避免 `#FFC107` 浅琥珀白底不可读）
- 桥面"建议修改为"用 `#0070C0` 专业蓝（Office 标准色,律师惯用,严肃感强;避免正绿的商业活泼感）
- 功能绿 `#00A650` 仅保留为低风险标识，不再用于桥面条款修改建议

**风险等级呈现方式**：
- 统一使用 **扁平方块 `■`（U+25A0 BLACK SQUARE）+ 文字颜色染色** 取代 emoji 圆球 `🔴🟡🟢`
- 原因：Word 渲染 emoji 会呈现带高光的立体球，破坏扁平化商务感
- 在 Python 脚本中：`run.add_run("■ 高风险")` 配合 `set_run_font(run, color=COLOR_RED)` 实现
- 在 SVG 中：使用 `<rect>` 绘制 14x14 正方形，配语义色填充

用于一切视觉呈现（流程图、表格、架构图、装饰线条、图例、图标底色等）。

### 2.4 配色的哲学

为什么选这几个色系？

**blue（高端蓝）作为主色**：
- 比 indigo 少一分紫调，更纯正
- 比 sky 多一分深沉，更商务
- 与法律行业的严肃气质匹配
- Bloomberg、Goldman Sachs 等金融机构主色在此区间

**teal（青绿）作为辅助**：
- 温和、协作、柔和
- 与 blue 形成互补（冷色调内部的对比）
- 避免使用过于鲜艳的"饱和绿"

**amber（琥珀）作为第三色**：
- 温暖、合作
- 比"金色"更克制
- 不会与功能色的"标准橙 #FF9900"混淆（一个是美学琥珀 #F59E0B，一个是功能橙 #FF9900）

**rose（玫红）作为警示**：
- 比正红柔和
- 作为美学层的警示色，不与功能层的 `#FF0000` 冲突

**slate（石板灰蓝）作为中性基调**：
- 比纯灰暖，比纯蓝冷
- 现代感强，不土气
- Tailwind 默认色盘的基础色，被大量现代 UI 采用

### 2.5 禁用色清单

以下色值在本 Skill 的美学场景中**禁止使用**：

| 禁用色 | 原因 |
| --- | --- |
| 深红 `#C00000` | 作者个人品牌色，仅在课件 / 封面等品牌物料使用 |
| 金色 `#E8A500` | 作者个人品牌色，同上 |
| 深绿 `#548235` | 作者个人品牌色，同上 |
| 靛蓝系 `#4F46E5` `#6366F1` 等 indigo | 本 skill 使用 blue 系,indigo 禁用（避免紫调） |
| 纯黄 `#FFFF00` | 白底不可见，视觉污染 |
| 荧光绿 `#00FF00` | 过于刺激，不符合商务感 |
| 皇家蓝 `#4169E1` | 过时配色 |
| Office 默认橙 `#ED7D31` | 过时审美 |
| Office 默认蓝 `#4472C4` | 过时审美 |
| 任何饱和度超过 90% 的俗气色 | 破坏专业气质 |
| 任何渐变色 | 违反扁平化原则 |

## 三、字体系统

### 3.1 字体选择原则

**本 Skill 统一字体规范**：

| 用途 | 中文字体 | 英文字体 / 数字字体 | 备注 |
| --- | --- | --- | --- |
| **标题** | **微软雅黑** | Times New Roman | 层次明确，视觉权重足 |
| **正文** | **宋体** | Times New Roman | 正式严肃，适合法律文书 |
| **数字（金额 / 日期 / 百分比 / 条款号）** | —— | **Times New Roman** | 全局统一，对齐易读 |
| SVG / 静态图 | PingFang SC / Microsoft YaHei | Times New Roman / Helvetica Neue | 屏幕显示 fallback |
| 代码 / 编号 | 等线 Light / Consolas | Consolas / Monaco | 等宽，便于对齐 |

**核心规则（强制）**：
- **所有英文字符与数字一律使用 Times New Roman**——金额、日期、百分比、条款编号、稳定 ID 等全部走同一英文字体，确保视觉统一
- **所有标题中文字符使用微软雅黑**——视觉权重充足，适合标题层级
- **所有正文中文字符使用宋体**——正式严肃，符合法律文书惯例
- 中英混排时，中文字符自动采用 eastAsia 字体（微软雅黑 / 宋体），英文和数字自动采用 ascii 字体（Times New Roman）

**设计依据**：
- **微软雅黑** + **Times New Roman**：Windows / Mac / Office 365 均默认预装，读者无需额外安装字体即可正确渲染
- **宋体**：正文中文的法律文书标准字体，辨识度高，印刷质量稳定
- **Times New Roman**：金融、法律、学术领域数字与英文的通用字体，与宋体、微软雅黑的衬线 / 非衬线对比平衡

**SVG 字体 fallback 链（强制）**：

所有 SVG 文件必须使用以下完整 fallback 链，兼容 Mac / Windows / Linux / 移动端：

```
font-family="'PingFang SC','Microsoft YaHei','Noto Sans SC','Helvetica Neue',Arial,sans-serif"
```

### 3.2 字号层级

**Word 文档字号**：

| 层级 | 字号 | 字体 | 字色 | 用途 |
| --- | --- | --- | --- | --- |
| H1 | 三号（16pt） | 宋体加粗（Word 内建 Heading 1 样式） | 黑色 | 章节主标题（一、二、三...） |
| H2 | 四号（14pt） | 宋体加粗（Word 内建 Heading 2 样式） | 黑色 | 节标题（2.1 / 2.2 / 2.3...） |
| **风险项标题** | 四号（14pt） | **宋体 + TNR**（非微软雅黑） | 黑色（仅 ■ 级别用风险色） | "风险 01 ■ 高风险 xxx" |
| **评级/判断行** | 四号（14pt） | 宋体 + TNR | 黑色（仅 ■ 级别用风险色） | 执行摘要的"评级: / 判断:" |
| Body | 小四（12pt） | 宋体 | 黑色 | 正文（两端对齐） |
| Small | 五号（10.5pt） | 宋体 | 黑色 / 中灰 | 脚注、注释、图例说明 |
| Mini | 小五（9pt） | 宋体 | 中灰 | 极小注释（谨慎使用） |

**关键规则（强制要求）**：
- **一级、二级标题一律黑色**（`add_heading_black` 实现，全局黑字原则优先）——专业蓝 `#0070C0` 仅用于桥面条款"建议修改为"引导语、稳定 ID 等点缀元素
- 标题应用 Word 内建 Heading 1 / Heading 2 样式，保证导航窗格可用
- **风险项标题用宋体而非微软雅黑** — 因为风险项标题本质是"加粗的正文大字号"，不是结构性标题
- **评级行、判断行用四号而非小三** — 字号不应大于二级标题，避免层级倒置
- **除 "■ 高/中/低风险" 外，风险项标题其他部分必须是黑色** — 避免多色造成视觉喧闹

**正文对齐（强制）**：
- 所有正文段落**两端对齐**（Justify）
- 居中的部分仅限：封面主标题、封面信息表、章节首段居中说明（极少数场景）
- 实现方式：设置文档 `Normal` 样式的 `paragraph_format.alignment = JUSTIFY`

**SVG / 静态图字号**（像素单位）：

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 大标题 | 28-30px | 700 | 图表主标题 |
| 副标题 | 13.5-14px | 400 | 路径式副标题 |
| 节点主标题 | 16-17px | 700 | 卡片内主标题 |
| 节点副标题 | 12px | 400 | 卡片内第二行描述 |
| 节点注释 | 11px | 400 | 卡片内第三行注释 |
| 图例文字 | 11px | 400 | 图例说明 |
| 胶囊标签 | 11px | 600 | 分支标签、状态标签 |
| 底部版权 | 10px | 400 | 版权声明 |

**字号层级强制规则**：
- 同级元素字号必须一致
- 不同级别元素必须有视觉差异（不能 16pt 和 15pt 并存而不区分）
- 正文一律 12pt，不因个别段落"想突出"而放大

### 3.3 字重规则

- 标题一律**加粗**（黑体本身已视觉加重，但软件标注仍需 bold / font-weight: 700）
- 正文一般不加粗；强调内容用"**加粗**"标注（不改字号、不改颜色）
- 数字在正文中一律**正常字重**，表格中**可选加粗**
- 斜体**极少使用**（中文斜体视觉差）

## 四、版式规范

**版式**是决定一张图是否"高级"的关键——配色对了但版式乱，仍然土气；配色朴素但版式严谨，仍然高级。

### 4.1 整体版式的三层骨架

任何一张 SVG 静态图（架构图、流程图、示意图）都应遵循以下三层骨架：

```
┌─────────────────────────────────────────────┐
│  顶部标题区 Y=0-130                         │
│  ├── 大标题（28-30px 加粗深色）            │
│  ├── 路径式副标题（A → B → C → D）         │
│  └── 图例栏（可选，Y=128 附近）             │
├─────────────────────────────────────────────┤
│                                             │
│  中部内容区 Y=130-?                         │
│  ├── 层级结构：输入 → 主块 → 输出            │
│  ├── 深色主块（占画面 30-40%）               │
│  ├── 浅色卡片（层级式分布）                  │
│  └── 连线与箭头（严格对齐）                  │
│                                             │
├─────────────────────────────────────────────┤
│  底部核心洞察区 Y=底部往上 150-200          │
│  ├── 分隔细线（中性 200）                   │
│  ├── 主色加粗核心洞察（一句点题）            │
│  ├── 灰色补充说明（1-2 行）                 │
│  └── 最底部版权（极浅灰 10px）              │
└─────────────────────────────────────────────┘
```

**三层骨架的间距规则**：
- 顶部标题区与内容区之间至少留 30px
- 内容区内部模块间隔 40-50px
- 底部核心洞察区顶部必有 1px 中性 200 分隔线
- 分隔线上下至少各留 30px

### 4.2 主块设计（深色饱和大块）

**主块是版面的视觉重心**。用于呈现 Skill 的核心处理模块、重要流程主体、架构图的中心层。

**规格参数**：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 填充色 | `#003153`（主色 950 · 海军蓝） | 首选(与 `examples/01-architecture-sample.svg` 标杆一致) |
| 边框 | 无 | 纯色块，不描边 |
| 圆角 | `rx="16" ry="16"` 到 `rx="18" ry="18"` | 大圆角是"现代感"的核心 |
| 占画面比例 | 30%-45% | 太小失重心，太大压迫 |
| 内部文字 | 白色主文字 + `#BFDBFE` 主色 200 副文字 | 双层文字保证层级 |

**主块内部结构**：

```
┌───────────────────────────────────────────────────────┐
│                                                       │
│     主块标题（22-24px 白色加粗，居中）               │
│     主块副标题（12-13px #BFDBFE，居中）              │
│                                                       │
│   ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  │  ← 虚线分隔（主色 400 / opacity 0.6）
│                                                       │
│   ┌─────────────────┐   ┌─────────────────────┐     │
│   │  左半内容        │   │  右半内容            │     │
│   │                 │   │                     │     │
│   └─────────────────┘   └─────────────────────┘     │
│                                                       │
└───────────────────────────────────────────────────────┘
```

**主块内的文字色规则**：
- 主标题：`#FFFFFF` 纯白加粗
- 副标题 / 说明：`#BFDBFE` 主色 200（浅蓝白）
- 强调小块内二级文字：`#E0E7FF` 或 `#DBEAFE`

### 4.3 浅色卡片设计（信息承载单元）

**浅色卡片用于**：输入卡、输出卡、交付卡、辅助信息展示等非核心但必要的信息。

**四种卡片色系**（对应美学色系）：

| 卡片类型 | 填充色 | 边框色 | 主标题色 | 副文字色 | 语义 |
| --- | --- | --- | --- | --- | --- |
| 主色卡片 | `#DBEAFE` | `#2563EB` | `#172554` | `#1E40AF` + `#2563EB` | 主业务、甲方、重要 |
| 青绿卡片 | `#CCFBF1` | `#14B8A6` | `#134E4A` | `#0F766E` + `#14B8A6` | 次业务、乙方、协作 |
| 琥珀卡片 | `#FEF3C7` | `#F59E0B` | `#78350F` | `#B45309` + `#D97706` | 双方、合作、温和 |
| 玫红卡片 | `#FFE4E6` | `#F43F5E` | `#881337` | `#BE123C` + `#E11D48` | 异常、警示、合同解除 |

**卡片规格**：
- 圆角：`rx="12" ry="12"` 到 `rx="14" ry="14"`
- 边框宽度：`stroke-width="1.5"`
- 内部 padding（内容距边）：左右各 20px、上下各 16px
- 卡片宽度：220-450px（单张卡片），四并列时单卡 250-280px
- 卡片高度：90-140px（视内容量）

### 4.4 胶囊标签设计（状态与分支标记）

**胶囊标签用于**：流程图的分支条件（合格/不合格）、循环回路标签、异常升级标签、状态小标识。

**规格**：

| 参数 | 值 |
| --- | --- |
| 形状 | 圆角矩形（`rx="11" ry="11"` 或 `rx="12" ry="12"`） |
| 填充 | `#FFFFFF` 白底（统一） |
| 边框宽度 | `stroke-width="1.2"` |
| 边框色 | 随语义变化（见下表） |
| 内文字号 | 11px |
| 内文字重 | 600 |
| 高度 | 22-26px |
| 宽度 | 视文字而定（文字左右各留 14px 呼吸） |

**胶囊色彩与语义对应**：

| 语义 | 边框色 | 文字色 | 示例 |
| --- | --- | --- | --- |
| 正面分支（合格 / 通过） | `#14B8A6` 青绿中 | `#0F766E` 青绿深 | "合格"、"通过" |
| 负面分支（不合格 / 拒绝） | `#F59E0B` 琥珀中 | `#B45309` 琥珀深 | "不合格"、"驳回" |
| 业务循环（正常返回） | `#14B8A6` 青绿中 | `#0F766E` 青绿深 | "整改完成 · 重新验收" |
| 异常升级（警示） | `#F43F5E` 玫红中 | `#BE123C` 玫红深 | "累计 3 次不合格" |
| 中性说明 | `#E2E8F0` 中性 200 | `#475569` 中性 600 | 普通条件说明 |

### 4.5 三行文字结构（信息密度控制）

**核心原则**：任何承载信息的卡片 / 节点内，文字都应遵循"标题 / 参数 / 时间"三行结构，字号递减，颜色深度递减。

**结构示例**（以甲方节点为例）：

```
┌──────────────────────────────────────┐
│                                      │
│       甲方支付预付款                  │  ← 第一行：主标题（16px bold 深色）
│       30%  ·  人民币 25.8 万元        │  ← 第二行：关键参数（12px 中深色）
│       合同签署之日起 5 个工作日内      │  ← 第三行：时间 / 注释（11px 浅色）
│                                      │
└──────────────────────────────────────┘
```

**每行的用途**：
- 第一行 **做什么**：动作、事项名称，最醒目
- 第二行 **参数**：金额、比例、数量、主体、规格
- 第三行 **时间 / 条件**：何时完成、触发条件、法规引用

**字号与字色（以主色卡片为例）**：

| 行 | 字号 | 字重 | 字色 | 对齐 |
| --- | --- | --- | --- | --- |
| 主标题 | 16px | 700 | `#172554` | 居中 |
| 参数 | 12px | 400 | `#1E40AF` | 居中 |
| 时间 / 注释 | 11px | 400 | `#2563EB` | 居中 |

**行间距**：约 20-24px（视觉呼吸感）

**禁止**：
- 长段落文字堆在一起（信息密度失控）
- 单行超过 15 个汉字（换行到下一行，而非超宽）
- 字号跳跃不连续（不能主标 16px、副标直接 11px，中间缺 12px 过渡）

### 4.6 路径式副标题（顶部导览）

**路径式副标题**用文字加箭头描述整个流程的主线，位于大标题下方，形成"目录"效果。

**示例**：

```
技术服务合同 · 履约业务流程图
合同签署 → 预付款 → 交付 → 验收 → 进度款 → 质保期 → 尾款 → 履约完毕
```

**规格**：
- 字号：13-14px
- 字重：400（不加粗）
- 字色：`#64748B` 中性 500（淡化，避免抢大标题）
- 间隔符：半角空格 + 箭头 `→` + 半角空格（不用中文箭头）
- 整行居中
- 与大标题间距：30-35px

**路径项数规则**：
- 简单图：3-5 项（不要勉强凑）
- 复杂图：最多 8 项，超过则分行
- 每项用 2-6 个汉字，节奏感最好

### 4.7 底部核心洞察（一句点题）

**底部核心洞察**是整张图的"灵魂总结"——用一句主色加粗的话点明这张图的核心价值，灰色补充说明 1-2 行。

**位置**：画面底部向上 150-200px 处。

**结构**：

```
─────────────────────────────────────────────────────  ← 分隔线（中性 200）

    律师只定制 references/ 和审查立场，处理流程与脚本无需修改  ← 主色加粗句（16px，#1387C0）

    完整业务链路：合同文本 → 标准审查 Skill → 四件套 → 案件文件夹 → 下游 Skill 协同  ← 补充 1（12px，#64748B）
    清单可迭代：每次审查沉淀新发现 · checklist.md 越用越精准 · 律师专属审查经验资产化  ← 补充 2（12px，#64748B）

                    LEGAL AI TOOLMAKER · 法律工具制造者 | 缪奇川律师 出品  ← 底部版权（10px，#CBD5E1）
```

**规格**：
- 分隔线：`stroke="#E2E8F0" stroke-width="1"`，横贯全幅画面（留画面左右各 80px padding）
- 分隔线与核心句间距：35-40px
- 核心句字号：16px，字重 700，字色主色 `#1387C0`，居中
- 补充说明字号：12px，字重 400，字色 `#64748B`，居中
- 版权声明字号：10px，字色 `#CBD5E1`（极浅灰），居中

**核心洞察撰写规则**：
- 一句话原则（不超过 24 个汉字）
- 必须是"反直觉"或"可传播"的判断，不是中性描述
- 好示例：`律师只定制 references/，处理流程无需修改`（揭示系统设计哲学）
- 坏示例：`本图展示了合同审查的完整流程`（无信息量）

### 4.8 圆角半径规范

**圆角是扁平设计的核心符号**。圆角大小的统一决定整张图的"调性一致"。

| 元素 | 圆角半径 | 说明 |
| --- | --- | --- |
| 深色主块 | `rx="16"` 到 `rx="18"` | 大圆角，传递"现代感" |
| 浅色卡片 | `rx="12"` 到 `rx="14"` | 中等圆角，标准卡片 |
| 表格外框 | `rx="10"` | 适中圆角 |
| 胶囊标签 | `rx="11"` 到 `rx="12"` | 接近半圆高度 |
| 终端节点（胶囊形） | `rx="34"` 或等于高度的一半 | 完全胶囊 |
| 图标底色小块 | `rx="3"` 到 `rx="4"` | 小圆角，装饰性 |
| 图例小色块 | `rx="3"` | 极小圆角 |

**圆角禁忌**：
- 不使用 `rx="0"`（直角过于生硬）
- 不使用 `rx="1"` 或 `rx="2"`（几乎看不见的圆角，画面依然像直角）
- 不使用过大圆角（`rx="30"+` 在非胶囊场景显得浮夸）

## 五、连线与箭头规范

连线与箭头是流程图、架构图的"骨骼"。本章节把连线规范独立成章,因为这套规则适用于所有 SVG 视觉输出。

### 5.1 三类连线的语义分工

本 Skill 的所有可视化图表，连线**必须且仅能**使用以下三类语义之一：

| 类别 | 线型 | 色系 | 语义 | 使用场景 |
| --- | --- | --- | --- | --- |
| **主流程** | 实线 | 中性 slate | 正常业务推进 | 所有主线路径、判断分支实线 |
| **循环回路** | 虚线 | 青绿 teal | 业务正常循环 / 反馈 | 整改→重新验收、增量检索→回查、迭代→更新 |
| **异常升级** | 虚线 | 玫红 rose | 警示路径 / 升级 / 终止 | 3 次不合格→合同解除、违约→诉讼 |

**禁用**：
- 主流程用虚线（语义混淆）
- 循环用灰色虚线（失去语义强度）
- 异常用实线（失去警示感）
- 同一张图用两种以上的虚线样式

### 5.2 箭头 marker 设计

**统一箭头形状**：带尾部缺口的尖三角（Linear / Figma 风格），而非传统的空心三角或完整实心三角。

**SVG marker 定义**（复制即用，四色版本）：

```xml
<defs>
  <marker id="arrowSlate" viewBox="0 0 12 12" refX="10" refY="6"
          markerWidth="7.5" markerHeight="7.5" orient="auto">
    <path d="M 0 1 L 12 6 L 0 11 L 3 6 Z" fill="#64748B"/>
  </marker>
  <marker id="arrowBlue" viewBox="0 0 12 12" refX="10" refY="6"
          markerWidth="7.5" markerHeight="7.5" orient="auto">
    <path d="M 0 1 L 12 6 L 0 11 L 3 6 Z" fill="#1387C0"/>
  </marker>
  <marker id="arrowTeal" viewBox="0 0 12 12" refX="10" refY="6"
          markerWidth="7.5" markerHeight="7.5" orient="auto">
    <path d="M 0 1 L 12 6 L 0 11 L 3 6 Z" fill="#14B8A6"/>
  </marker>
  <marker id="arrowRose" viewBox="0 0 12 12" refX="10" refY="6"
          markerWidth="7.5" markerHeight="7.5" orient="auto">
    <path d="M 0 1 L 12 6 L 0 11 L 3 6 Z" fill="#F43F5E"/>
  </marker>
</defs>
```

**关键参数说明**：
- `markerWidth / markerHeight = 7.5`：精致但清晰，不过大
- `refX="10"`：让箭头尖贴紧连线终点
- `d="M 0 1 L 12 6 L 0 11 L 3 6 Z"`：尾部切入 3px 形成缺口，比传统三角精致
- `orient="auto"`：箭头自动跟随路径方向

**不使用**：
- 默认 Mermaid 箭头（笨重）
- 空心三角（弱化箭头指向性）
- 方头箭头（非流程图语义）

### 5.3 dasharray 节奏

**虚线节奏**决定整张图的"呼吸感"。

**统一参数**：
```
stroke-dasharray="7 4"
```

即实线段 7px、间隙 4px 循环。这个节奏的逻辑：
- 实线段略长于间隙 → 视觉上仍能识别为"线"而非"点"
- 节奏足够紧 → 不会显得稀疏
- 节奏足够松 → 保持呼吸感

**禁用**：
- `"5 5"`（节奏平均，无张力）
- `"2 2"`（过密，视觉上变成"虚晕"）
- `"10 3"`（实线段过长，几乎像实线）
- 点划线 `"8 3 2 3"`（太花哨）

### 5.4 S 曲线贝塞尔路径

**循环回路必须用平滑 S 曲线**，而非拼接多段 Q 曲线或直角折线。

**标准 S 曲线模板**（以"整改完成 → 重新验收"为例）：

```xml
<path d="M 1010 770 V 725 C 1010 698, 820 698, 720 762"
      stroke="#14B8A6" stroke-width="1.8" stroke-dasharray="7 4" fill="none"
      marker-end="url(#arrowTeal)"/>
```

**路径拆解**：
- `M 1010 770`：起点（循环起始节点的顶部中点）
- `V 725`：短距离垂直上升（给 S 曲线一个起始直线段，避免突变）
- `C 1010 698, 820 698, 720 762`：三次贝塞尔曲线
  - 控制点 1 `(1010, 698)`：继续向上（与起点同 x，确保曲线平滑上扬）
  - 控制点 2 `(820, 698)`：中间上方（与控制点 1 同 y，形成平顶弧）
  - 终点 `(720, 762)`：目标节点的斜边上（进入点）

**设计逻辑**：
- **两个控制点同 y 值** → 曲线形成"平顶拱形"，视觉上像一条被轻轻拉起的线
- **先 V 再 C** → 起点有一小段垂直延伸，避免曲线紧贴节点顶部产生突兀
- **终点定在斜边 / 边缘上** → 箭头指向节点内部，避免箭头穿透节点

**标签位置**：放在 S 曲线的最高点（y 最小处）上方 10-15px，用胶囊容器承载。

### 5.5 分支标签容器规范

**所有分支条件（合格 / 不合格 / 累计 3 次不合格 / 整改完成）都必须用胶囊标签承载，严禁文字直接浮在连线上**。

**胶囊标签规格**（参见 4.4 节详细规范）：
- 白底
- 圆角 `rx="11"` 到 `rx="12"`
- 边框色对应语义（青绿 / 琥珀 / 玫红 / 中性）
- 字号 11px，字重 600
- 内容左右各留 14px 呼吸空间

**标签放置位置**：
- 直线分支：标签居中于连线中点，微偏（避免压线）
- S 曲线：标签位于曲线最高点上方 10-15px
- 长距离连线：标签在连线 1/3 或 2/3 处

### 5.6 连线色板对应表

快速查表：

| 用途 | stroke | stroke-width | stroke-dasharray | marker |
| --- | --- | --- | --- | --- |
| 主流程连线 | `#64748B` | `2` | 无 | arrowSlate |
| 循环回路连线 | `#14B8A6` | `1.8` | `7 4` | arrowTeal |
| 异常升级连线 | `#F43F5E` | `1.8` | `7 4` | arrowRose |

## 六、表格规范

表格是本 Skill 最常见的视觉元素。一个精心设计的表格本身就是"交付极度优雅"的体现。

### 6.1 表格类型选择

本 Skill 推荐使用**三线表**作为默认表格样式。理由：
- 视觉简洁，商务感强
- 信息层级清晰
- 学术、商务、法律领域通用

**三线表结构**：
- 顶部粗线（1.5pt）
- 表头底部细线（0.75pt）
- 底部粗线（1.5pt）
- 行间无线（或极浅的中性 200 色分隔线）

**不推荐**：
- 全框线网格表（视觉过重）
- 无边框表格（信息边界不清）
- 彩色边框表（破坏专业感）

## 八、SVG 静态图生成规范

### 8.1 何时用 SVG 而非 Mermaid

**Mermaid 的局限**：
Mermaid 生成的流程图符合基础可用性，但在以下方面无法达到"交付极度优雅"的水准：
- 无法精细控制圆角、间距、字号层级
- 节点文字不支持三行结构的差异化字号
- S 曲线贝塞尔路径不可精细控制
- 胶囊标签容器无法实现
- 图例栏需要额外 HTML 包装

**SVG 的使用场景**：
- **架构图、结构示意图** → 必须用 SVG（Mermaid 无法实现复杂版式）
- **流程图** → 默认用 Mermaid，但对"出版级""折页印刷""GitHub 主页封面"等关键场景，改用手写 SVG
- **表格示意、图表示意** → 必须用 SVG

**简单原则**：
- 关键展示面（首图、封面、README 顶部）→ SVG
- 报告中间的常规流程 → Mermaid

### 8.2 SVG 模板结构

所有 SVG 静态图必须遵循以下模板结构：

```xml
<svg xmlns="http://www.w3.org/2000/svg"
     viewBox="0 0 {宽} {高}"
     width="{宽}" height="{高}"
     font-family="'PingFang SC','Microsoft YaHei','Noto Sans SC','Helvetica Neue',Arial,sans-serif">

  <!-- 1. 定义区 defs -->
  <defs>
    <!-- marker 箭头定义（四色） -->
    <!-- clipPath 剪裁路径（如表格圆角需要） -->
  </defs>

  <!-- 2. 背景 -->
  <rect width="{宽}" height="{高}" fill="#FFFFFF"/>

  <!-- 3. 顶部标题区 Y=0-130 -->
  <text ... 大标题 ...>
  <text ... 路径式副标题 ...>
  <!-- 可选：图例栏 Y=128 附近 -->

  <!-- 4. 中部内容区 Y=130-? -->
  <!-- 按业务逻辑组织深色主块、浅色卡片、连线 -->

  <!-- 5. 底部核心洞察区 Y=底部向上 150-200 -->
  <line ... 分隔线 ...>
  <text ... 主色加粗核心句 ...>
  <text ... 灰色补充 ...>
  <text ... 版权 ...>

</svg>
```

### 8.3 标准 marker 定义库

每个 SVG 文件的 `<defs>` 区**必须**包含四色箭头 marker（即使当前图只用了一部分）。代码见 5.2 节。

这样做的好处：
- 跨 SVG 文件复用一致
- AI 生成新图时可直接引用
- 便于批量升级（改一处影响全部）

### 8.4 字体 fallback

SVG 文件必须在 `<svg>` 标签或每个 `<text>` 标签上声明完整字体 fallback 链：

```
font-family="'PingFang SC','Microsoft YaHei','Noto Sans SC','Helvetica Neue',Arial,sans-serif"
```

**各平台渲染效果**：
- Mac → 渲染为 PingFang SC（苹方）
- Windows → 渲染为 Microsoft YaHei（微软雅黑）
- Linux / 服务器 → 渲染为 Noto Sans SC（思源黑体）
- 英文环境 → 回退到 Helvetica Neue / Arial

### 8.5 viewBox 与响应式

**推荐 viewBox 尺寸**：

| 图类型 | 推荐尺寸 | 说明 |
| --- | --- | --- |
| 架构图（竖版） | `0 0 1240 1560` | 与 A4 比例接近 |
| 流程图（竖版） | `0 0 1240 1480` | 适中 |
| 表格示意 | `0 0 1240 1200` | 横幅 |
| 横版架构图 | `0 0 1600 900` | 16:9，适合 GitHub README 头图 |

**设计 vs 响应式**：
- 所有元素在 viewBox 内用绝对定位（x / y 数值），保证精确
- 最外层 SVG 声明 `width` `height` 与 viewBox 数值一致，便于下载保存
- 嵌入网页时可用 CSS 覆盖 `width: 100%; height: auto;` 实现响应式

- 标题上下必须有空行
- 表格前后必须有空行

- 章节标题不单独在页底（孤行）

- 一段内容的首行不单独在页末（widow）
- 段末最后一行不单独在次页顶部（orphan）
