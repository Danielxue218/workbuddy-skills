# 组织立场手册模板 playbook-template.md

> **场景极度垂直 · SOP 极度精简 · 交付极度优雅**
>
> 本文件是 **playbook 机制**的模板。Playbook 是架在 `checklist.md` 之上的一层——让律所 / 法务部 / 企业把自己的"组织立场"写成一份规则文档，审查时和清单联用，输出更贴合本组织要求的审查结果。
>
> Playbook 是**可选组件**。不加载它，Skill 按 checklist 默认标准执行；加载它，Skill 会在 checklist 判断之上追加"本组织立场"的覆盖规则。
>
> **机制来源**：Anthropic 官方合同审查 skill 的 playbook 机制；**本地适配**：结合中国法律实务场景与 mqc-contract-review-standard 的稳定 ID 系统。

---

## 一、Playbook 是什么

### 1.1 不加载 playbook 时

Claude 按 `checklist.md` 的默认标准判断。比如违约金条款（C021）：
- 超过合同总金额 30% → ■ 高风险
- 10%-30% 区间 → ✓ 正常
- 低于 5% → ■ 低风险

这是**通用律师共识**。

### 1.2 加载 playbook 后

Claude 在 checklist 判断之上叠加**本组织的覆盖规则**。比如某律所 playbook 写：

```
C021 违约金比例（覆盖）
- 本所立场：作为乙方时，我方违约金上限 15%
- 超过 15% 即使未超 30%，也升级为 ■ 高风险
- 原因：本所服务类合同多为长期合同，15% 以上曾导致多次争议
```

这样同一份合同、同一个 C021 检查项，用不同律所的 playbook 审出来的结果就会不同——**因为每个律所的"可接受边界"本来就不同**。

### 1.3 Playbook 的三个典型用途

| 用途 | 举例 |
| --- | --- |
| **阈值定制** | 把 checklist 的"30%"改成本组织的"15%"或"50%" |
| **新增红线** | checklist 没覆盖的条款（"不得含任何单方变更权"） |
| **例外豁免** | 本组织特殊业务下可容忍的条款（"作为金融乙方，最低预付款可降至 10%"） |

## 二、Playbook 和 Checklist 的关系

这是最重要的理解点。

### 2.1 两者是"叠加"不是"替代"

```
┌─────────────────────────────────────────────────┐
│  Layer 1 · checklist.md（标准层 · 通用律师共识）  │
│  60 项 × 12 维度，数字化阈值，L1/L2/L3 层级      │
└─────────────────────────────────────────────────┘
                       ↓ 叠加
┌─────────────────────────────────────────────────┐
│  Layer 2 · playbook.md（组织层 · 本组织立场）     │
│  覆盖 · 新增 · 豁免 三类规则                     │
└─────────────────────────────────────────────────┘
                       ↓ 审查
┌─────────────────────────────────────────────────┐
│  审查报告 · 注明"基于 checklist v1.0 + playbook  │
│  [组织名] v1.0 执行"                             │
└─────────────────────────────────────────────────┘
```

### 2.2 冲突时的优先级

**Playbook 优先于 checklist**。

举例：
- checklist C021 说"违约金 20% = ✓ 正常"
- playbook 说"本所立场 C021 违约金超过 15% 即 ■ 高风险"
- 审查结论：■ 高风险（playbook 覆盖）

在审查报告里明确标注：**"本项触发 playbook [组织名] 的覆盖规则，原 checklist 默认判断为 ✓ 正常"**，保证可追溯。

### 2.3 什么时候该用 playbook 而不是直接改 checklist

**用 playbook 的情形**：
- 本组织立场与通用律师共识有分歧，但不想改通用清单
- 同一个 Skill 用户使用者多（多个律所、多个法务部），每家要求不一样
- 组织立场可能经常调整（如季度复盘后调整阈值），不想每次都改 checklist

**直接改 checklist 的情形**：
- 发现 checklist 本身有错（漏项、条文错误）
- 新增一类通用律师都认同的检查项
- 升级 checklist 到新版本（如补充新法规）

**推荐做法**：checklist 保持为通用版本，每家律所 / 法务部维护一份自己的 playbook。

## 三、Playbook 的三类规则

每条 playbook 规则必须归属于以下三类之一。

### 3.1 覆盖规则（Override）

**作用**：修改 checklist 中某一项的判断标准。

**格式**：

```
## [规则编号] · [检查项 ID] · [简短描述]

- **类型**：覆盖
- **对应 checklist**：C021（违约金比例）
- **覆盖内容**：
  - checklist 默认：超过 30% = ■ 高风险
  - 本组织标准：超过 **15%** = ■ 高风险；10%-15% = ■ 中风险；低于 10% = ✓ 正常
- **覆盖原因**：本所服务类合同多为 12 个月以上长期合同，
  15% 以上违约金在 2024-2025 年实务中曾引发三次争议，
  经合伙人会议决议调整阈值。
- **适用条件**：仅服务合同（技术服务 / 咨询服务 / 运维服务）；
  买卖合同和建筑工程合同**不适用**。
- **立场**：乙方立场
- **生效日期**：2026-01-01
- **复核日期**：2026-12-31
```

**覆盖规则的关键要求**：
- 必须指向 checklist 的稳定 ID（C001-C060）
- 必须说明覆盖原因（不是"因为老板说了算"这种无法复现的理由）
- 必须说明适用条件（什么情况下这条覆盖生效、什么情况下失效）
- 必须说明立场（甲方 / 乙方 / 中性）
- 必须有生效和复核日期

### 3.2 新增规则（Additional）

**作用**：增加 checklist 没有的检查项。

**格式**：

```
## [规则编号] · 新增 · [简短描述]

- **类型**：新增
- **不对应任何 checklist 项**（因为是本组织特有）
- **检查内容**：
  - 检查项：合同是否含"单方变更条款通知期"
  - 判断标准：通知期短于 30 日 = ■ 高风险；
    30-60 日 = ■ 中风险；超过 60 日 = ✓ 正常
- **新增原因**：本所承接的国企合同常含此类条款，2025 年发生过
  甲方单方缩短通知期导致乙方措手不及的案例。
- **适用条件**：涉及国企或大型央企作为甲方的合同
- **立场**：乙方立场
- **识别线索**：合同中出现"本合同条款可由甲方单方调整""甲方有权随时修改"
  等表述，且附近有"通知期 X 日"的约定
- **修改建议**：建议改为"任何变更须经双方书面协商一致，
  一方单方通知的，至少提前 60 日书面告知"
- **生效日期**：2026-01-01
```

**新增规则的关键要求**：
- 必须有完整的"检查项 + 判断标准 + 识别线索 + 修改建议"四件套（和 checklist 的单项结构一致）
- 新增规则的编号格式：`PB-[组织代码]-[序号]`，如 `PB-DYLAW-001`（东友律师事务所新增规则第 1 条）
- 规则足够成熟后可考虑反向回归到通用 checklist（通过公开 PR 给 checklist 贡献新项）

### 3.3 豁免规则（Exemption）

**作用**：在特定条件下豁免 checklist 某一项的触发。

**格式**：

```
## [规则编号] · 豁免 · [简短描述]

- **类型**：豁免
- **对应 checklist**：C012（预付款比例）
- **豁免内容**：
  - checklist 默认：预付款超过 50% = ■ 中风险（乙方立场时的 50% 以下反而是风险）
  - 本组织豁免：**作为金融机构乙方、且客户是央企信用主体时，
    最低预付款 10% 也接受**，不触发此 checklist 项
- **豁免原因**：本组织金融业务中，央企客户信用评级 AAA，
  历史零违约；过高预付款要求会流失客户。
- **适用条件**：同时满足以下三项——
  - 乙方是本组织金融条线
  - 甲方是央企（统一社会信用代码前缀 91）
  - 甲方信用评级 AAA（以最近 12 个月的报告为准）
- **立场**：乙方立场
- **生效日期**：2026-01-01
```

**豁免规则的关键要求**：
- 必须指向 checklist 稳定 ID
- 必须有明确的适用条件（通常是多项条件叠加）
- 必须能在合同文本或用户提供的背景信息中判断适用条件是否成立
- 若适用条件无法判断（如"信用评级"需要外部信息），应提示用户"需人工确认是否适用豁免"

## 四、Playbook 文件结构

每家组织维护自己的 playbook 文件，推荐文件名：

```
playbook-[组织代码].md
```

例如：
- `playbook-dylaw.md`（东友律师事务所）
- `playbook-companyA.md`（A 公司法务部）
- `playbook-miuqichuan-personal.md`（律师个人版）

### 4.1 完整文件模板

```markdown
---
```

### 4.2 规则数量建议

| 组织类型 | 建议 Playbook 规则数 | 原因 |
| --- | --- | --- |
| 律所个人版 | 3-10 条 | 个人风格标注，不宜太多 |
| 中小律所 | 10-30 条 | 反映所级统一立场 |
| 大型律所 | 30-80 条 | 覆盖多业务条线的差异化 |
| 企业法务部 | 20-60 条 | 对应本企业主要业务模式 |

**原则**：playbook 规则数 ≤ checklist 项数（60）。如果超过，说明本组织立场和通用共识分歧过大，应考虑是否直接 fork 一份定制版 checklist 而非用 playbook。

## 五、Claude 加载 Playbook 时的执行逻辑

**本节是给 Claude 的执行指令。**

当用户在 Step 1 提供了 playbook 文件路径时，Claude 应按以下顺序处理：

### 5.1 加载阶段

1. 读取 playbook 文件，解析 frontmatter 和规则目录
2. 验证 `based_on_checklist` 版本号与当前 checklist.md 版本是否一致——不一致则提示用户"playbook 基于 checklist vX，当前 checklist vY，可能有规则失效，是否继续"
3. 按规则类型分组：覆盖规则 / 新增规则 / 豁免规则
4. 建立"checklist 项 ID → 覆盖 / 豁免规则"的映射表

### 5.2 执行阶段

对每一个 checklist 项（C001-C060），按以下顺序处理：

```
判断顺序（从上到下，先匹配者生效）：
1. 该项是否有豁免规则？且本合同是否满足豁免条件？
   └─ 是 → 不触发此 checklist 项，跳过
   └─ 否 → 进入 2
2. 该项是否有覆盖规则？且本合同是否符合覆盖规则的适用条件？
   └─ 是 → 按覆盖规则的阈值判断
   └─ 否 → 按 checklist 默认阈值判断
```

对每一个 playbook 新增规则，独立执行判断，产出发现条目（和 checklist 项同样的 7 字段结构）。

### 5.3 输出阶段

审查报告必须在以下位置明确标注 playbook 的影响：

- **封面"审查依据"字段**：`checklist v1.0.0 + [组织名] playbook v1.0.0`
- **每个触发 playbook 规则的发现**：标注"本发现触发 playbook [规则编号]，原 checklist 默认判断为 [XX]"
- **报告末尾新增"Playbook 覆盖汇总"章节**：列出本次审查中 playbook 覆盖了哪些 checklist 项的默认判断

## 六、Playbook 的维护建议

### 6.1 定期复核

Playbook 不是写完就放在那里的文件。建议：

- **每 6 个月**全面复核一次（是否仍反映本组织立场？是否有规则已过时？）
- **每次重大法规更新后**立即检索影响的规则
- **每 10 次合同审查**后回顾是否需要新增规则（清单外发现的沉淀）

### 6.2 从审查实践中反哺

每次审查后，Claude 会在报告的"清单外发现"章节列出 checklist 和 playbook 都未覆盖但值得关注的问题。**这是 playbook 迭代的核心输入**。

操作流程：
1. 审查完毕，查看"清单外发现"章节
2. 判断：这个发现是本组织独有的立场，还是通用律师共识
3. 本组织独有 → 写进 playbook（新增规则）
4. 通用共识 → 建议 PR 到 checklist 主仓库

### 6.3 团队内部 Review

Playbook 不应由单个律师拍板。建议：

- 新增覆盖 / 豁免规则需合伙人 / 法务负责人确认
- 阈值调整需要至少 2 位律师复核
- 定期在团队内分享 playbook 演进

## 八、重要声明

本文件是 **Playbook 模板**，本身不包含任何真实的组织立场规则。**请各组织基于本模板创建自己的 playbook 文件**，并遵守以下原则：

- 组织立场不得违反法律强制性规定（如"豁免违约金上限"不得突破民法典第 585 条）
- Playbook 仅供本组织内部使用，不对外披露
- 本模板不构成对任何具体组织立场的背书
