## 一、这是什么

这是一份**完全脱敏的示例案件**。包含一份虚构的技术服务合同、以及应用本 Skill 审查后生成的三份交付物。

所有当事人、金额、条款均为虚构,仅用于展示 Skill 的能力。**任何与真实合同的相似之处纯属巧合**。

## 三、原合同的 7 个"坑"

原合同是一份典型的**甲方主动方、乙方服务方**的技术服务合同(北京某科技公司委托上海某信息技术公司开发 CRM 系统,合同金额 86 万元,周期 12 个月)。

为了展示 Skill 的审查能力,合同中**精心设计了 7 个问题**,覆盖不同风险等级、不同维度、不同确认层级:

| # | 条款位置 | 问题 | 风险等级 | 对应清单 | 确认层级 |
| --- | --- | --- | --- | --- | --- |
| 1 | 第 3.1 条 | 大小写金额不一致(小写 86 万 · 大写"柒拾陆万") | ■ 高风险 | C010 | L1 |
| 2 | 第 8.1 条 | 违约金比例 35%(超过合同金额 30% 的酌减风险线) | ■ 中风险 | C021 | L3|精准审查|
| 3 | 第 8.3 条 | 双方逾期违约金标准差异 4 倍且日率畸高(日 5% vs 日 20%) | ■ 中风险 | C022 | L2 |
| 4 | 第 12.2 条 | 乙方承担无限连带责任且无合理限制 | ■ 高风险 | C025 | L3|精准审查|
| 5 | 第 12.3 条 | 竞业限制 2 年但未约定补偿金标准 | —(清单外发现) | 建议补充到四、权利与义务 | — |
| 6 | 第 15.1 条 | 送达地址不明确(未约定法定送达地址) | ■ 低风险 | C050 | L2 |
| 7 | 全文缺失 | 不可抗力条款缺失 | —(缺失条款) | C046 | — |

这 7 个坑分别出现在 3 份输出交付物的不同章节,便于您对照阅读。

## 四、建议的阅读方法

### 场景 A · 快速体验(5 分钟)

1. 翻开 `01-原合同-脱敏版.docx` 的第 2 页,找到 **3.1 条**:体会"小写 86 万、大写 76 万"的错位
2. 翻开 `03-审查报告-输出样例.docx` 的 **风险 02**:看 AI 如何识别、分析、给出桥面条款修改建议 —— **注意"修改建议"列里红色标注的改动字**,让您一眼看到改了什么
3. 翻开 `04-谈判优先级清单-输出样例.docx` 的 **Tier 1-02**:看同一个问题在谈判视角下的处理方式(含对方可能反驳 + 应对要点 + Plan B)

**一个问题,三种视角** —— 再打开修订批注版,看同一个问题在合同原文上被怎样改掉 —— 这就是八件套的价值。

### 场景 B · 律师实操视角(20 分钟)

假设您作为甲方律师收到乙方发来的这份合同,按以下顺序审查:

1. **先看合同概要** `02-合同概要-输出样例.docx` → 快速了解合同结构、金额、时限、当事方
2. **再看审查报告** `03-审查报告-输出样例.docx` → 全面评估风险:5 处风险项 + 1 处缺失条款 + 1 处清单外发现
3. **然后看谈判清单** `04-谈判优先级清单-输出样例.docx` → 制定谈判策略:哪些必须回绝、哪些争取修改、哪些可作筹码
4. **最后看原合同** `01-原合同-脱敏版.docx` → 对照定位具体条款位置

## 五、核心特性速览

### 5.1 视觉

- **封面**:包豪斯风格 · 浅蓝 #1387C0 细线 · 左对齐强网格 · 单页保证
- **标题**:所有一级/二级标题使用 Word 内建 Heading 样式,**打开 docx 后点击"视图→导航窗格"可看到完整大纲结构**
- **正文字体**:严格对齐图书《参考格式》—— 16/14/12pt 三级字号 · 1.5 倍行距 · 首行缩进 0.85cm · 两端对齐 · 数字英文 Times New Roman
- **颜色**:仅保留风险 ■ 方块的功能色(红/橙/绿)和修改建议的 #EE0000 正红标注,其他一切黑字

### 5.2 三列对照表

每个风险项的"当前条款 vs 修改建议"采用**两列并排表格 + 修改理由整行**:

```
┌────────────────────┬────────────────────┐
│  条款原文           │  修改建议(红字标注)  │
├────────────────────┼────────────────────┤
│ "...35% 的违约金"   │ "...**15%** 的..." │
├────────────────────┴────────────────────┤
│  修改理由(全宽整行)                      │
└──────────────────────────────────────────┘
```

律师一眼能看到:改了什么字(红色)、改成什么(右列)、为什么改(下行)。

### 5.3 规则来源 + 精准审查

审查报告每条风险带**规则来源**字段(标准清单 / Playbook 覆盖 / 清单外发现),并在第三章有"规则来源分布"节。关键条款标注**[精准审查]**,提示已独立重扫一遍。

### 5.4 维度图仅显示有风险的维度

第 3.4 节"风险分布维度图"只显示**有风险项的维度**,不展示空行。

### 5.5 业务流程图配色

`05-业务流程图.svg` 是 SVG 精美版(方案 A · 默认),严格对标 `examples/02-flowchart-sample.svg` 的视觉标准:浅蓝 `#003153` 作为终端节点主色、`#0070C0` 甲方、`#006A4E` 乙方、`#F6C12C` 双方、`#F5F0E1` 判断菱形、`#C92C2C` 异常。

如需批量生成(如一次审 20 份合同),可改用 Mermaid 自动版(方案 B · 降级),对应的源码模板见 `data/业务流程图.mmd`。

## 六、如何自己复现

如果您想基于本 Skill 审查其他合同,步骤如下:

```
[您的新合同.docx]
        ↓
加载本 Skill(mqc-contract-review-standard)
让 AI 逐条对照 checklist.md 扫描并产出结构化 JSON
        ↓
运行五个 Python 脚本
        ↓
[您的合同_合同概要.docx]
[您的合同_审查报告.docx]
[您的合同_谈判优先级清单.docx]
[您的合同_业务流程图.svg]
[您的合同_批注版.docx]        ← v2.0 新增
[您的合同_修订版.docx]        ← v2.0 新增
[您的合同_修订批注版.docx]    ← v2.0 新增
[您的合同_清洁版.docx]        ← v2.0 新增
```

脚本调用示例:

```bash
# 生成合同概要
python3 scripts/generate-summary.py \
    --output "新合同_合同概要.docx" \
    --data "summary-data.json"

# 生成审查报告
python3 scripts/generate-report.py \
    --output "新合同_审查报告.docx" \
    --data "report-data.json"

# 生成谈判优先级清单
python3 scripts/generate-negotiation.py \
    --output "新合同_谈判优先级清单.docx" \
    --data "negotiation-data.json"

# 生成业务流程图 · 方案 A:SVG 精美版(默认,推荐)
python3 scripts/generate-flowchart.py \
    --data "flowchart-data.json" \
    --output "业务流程图.svg"

# 生成文本四件(v2.0 新增):批注版 / 修订版 / 修订批注版 / 清洁版,一次全出
python3 scripts/generate-modified.py \
    --contract "01-原合同-脱敏版.docx" \
    --data "data/report-data.json" \
    --mode all \
    --output-dir "." \
    --contract-name "技术服务合同"

# 生成业务流程图 · 方案 B:Mermaid 自动版(降级,批量场景)
python3 scripts/render-flowchart.py \
    --input "业务流程图.mmd" \
    --output "业务流程图.png" \
    --inject-theme
```

**本目录下的 `data/*.json` 就是本示例合同的完整输入数据**,您可以参考其结构,为自己的合同准备同结构的 JSON。

### 6.1 JSON 关键字段速查

审查报告 `report-data.json` 里每个 finding 可以加:

```jsonc
{
  "rule_source": "checklist",       // checklist / playbook / extra
  "is_precise_review": true,        // 标记为精准审查项
  "suggestion_revised": "... **改动字** ...",  // 用 ** 包裹的文字会变成正红 #EE0000
  ...
}
```

谈判清单 `negotiation-data.json` 里的 `plan_b` 和 `suggested_text` 也支持 `**...**` 红字标注。

## 七、Skill 的审查结论摘要

对这份示例合同,审查得出的综合判断:

- **综合风险评级**:■ 中风险
- **可签性判断**:■ 修改后签约
- **核心结论**:本合同存在 2 处必须协商的高风险问题(无限连带责任、大小写金额不一致)和 2 处建议协商的中风险问题(违约金比例、双方不对等),其余为低风险或条款缺失。修改后可以签约。
- **Top 3 优先事项**:
  1. 乙方承担无限连带责任 → 立即与对方协商,无法修改则不签
  2. 大小写金额不一致 → 必须修正,保持一致
  3. 违约金比例超标 → 建议调整至 10%-20% 合理区间

## 八、局限性说明

本 demo-case 展示的是 **典型审查场景**。实际应用中,您可能遇到:

- 更复杂的合同类型(股权、并购、融资、建筑工程等)→ 建议等待对应专用 Skill,或基于 `playbook-template.md` 自行定制组织立场手册
- 更多的清单外发现 → 是 `checklist.md` 迭代的核心输入,欢迎反馈新的检查项
- 不同于本示例的立场组合 → 可通过切换 `review_stance` 参数(甲方/乙方/中性)获得不同视角
- 超长合同(100+ 页)→ 当前 Skill 建议拆分审查,后续会发布 `mqc-contract-review-batch` 处理
