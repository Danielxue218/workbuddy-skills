# demo · 建设工程施工合同纠纷 · 判决前冷推演

> 本 demo 用一个**真实、公开的最高人民法院指导性案例**，把本 skill 端到端跑一遍：
> 站在**承包人（原告）中天建设**一方，在**判决前**推演"能不能赢、赢在哪、输在哪、最坏到什么程度"，
> 再拿**真实判决结果**验证推演准不准。

---

## 一、选它的原因

**指导案例171号 · 中天建设集团有限公司 诉 河南恒和置业有限公司 建设工程施工合同纠纷案**
（案号 **(2019)最高法民终255号**，最高人民法院二审，2019.06.21）。

这一个案子几乎把本 skill 建设工程打样的**全部决定性要件与抗辩**都真实覆盖：工程款数额与结算依据、
合同无效参照有效、完工与质量、优先受偿权除斥期间、破产债权确认的程序前置、伪造公章 / 恶意串通的
证明标准陡增、造价鉴定的修正因素。且**结果公开可核**，可用来检验推演。

## 二、怎么跑的

**立场 = 原告向（中天）· 时态 = 前瞻（判决前）。** 输入是"中天代理律师在判决前掌握的材料"（`00-案情材料.md`），
引擎按**接案卡 → 六阶段动线 → 三张图**推进，产出律师版研判（结论先行）。**推演不看判决**；判决只在最后用于对照。

## 三、文件清单

| 文件 | 说明 |
| --- | --- |
| `00-案情材料.md` | 输入 · 中天代理律师判决前掌握的案情（当事人 / 事实 / 诉请 / 预期抗辩） |
| `01-接案卡.md` | 阶段一 · 五轴接案卡（含材料成熟度、缺口旗标、边界旗标） |
| `02-研判报告-原告向.md` | 六阶段研判（结论先行：一页纸摘要 → 六阶段详情 → 附件） |
| `maps/` | 三张图的 semantic-map.json（要件-证据矩阵 / 争议焦点 / 结果预判） |
| `out/` | 三张图渲染的 SVG / PNG，及 **`研判报告.docx`（Word 交付物，封面标准深红 #991B1B，嵌三图）** |
| `09-预判对照实判.md` | 推演结论 vs 真实判决，逐条验证 |
