# 置信度 · 溯源 · 降级纪律

> 本文件是引擎的**诚实纪律**，落地铁律②「三标出厂」。它管的是：引擎凭什么说一句话、
> 那句话有多硬、来源是什么、材料不足时怎么诚实降级而不是编造。
>
> **为什么这条纪律是本 skill 的立身之本**：本 skill 的差异化，是**诚实处理不确定性**——
> 律师的常态是"关键事实在对手或未来手里"。一个假装卷宗完整、给伪精确条号、把单方材料
> 当真相的工具（竞品的翻车方式），恰恰是我们要拒斥的。诚实不是修辞，是引擎的骨架。
> 本文件常驻生效于**每一阶段**，不是单独一步。

---

## 0. 阅读约定

- 凡须**执行**的标 **【规则】**；凡属**背景论证**标 *（理据）*。
- 本文件只管"怎么标、怎么降级"，**不管具体法律判断**（那在 `engine/`）。

---

## 1. 三标出厂（每一条结论的强制附签）

**【规则】** 引擎产出的**每一条实质结论**（一个请求权基础、一个要件的证明前景、一处裁判倾向、
一段结果区间），出厂强制带**三标**。缺任何一标，该结论不得交付。

| 标 | 回答 | 取值 |
|---|---|---|
| **① 置信度** | 这句话有多硬？ | 高 / 中 / 低 / 待核验（见 §2） |
| **② 来源** | 凭什么这么说？ | 已核验规范 / 类案（带层级）/ 数据库返回 / 模型推导 / 当事人陈述（见 §3） |
| **③ 立场方向** | 这对谁有利？ | 原告向 / 被告向 / 中立（客观）（见 §4） |

*（理据）* 三标各挡一种错误：置信度挡"把猜测说成定论"，来源挡"编造依据"，立场方向挡"客观与打法混用"。

---

## 2. 置信度四级（且**法律层面与证据层面必须分开评级**）

**【规则 · 两层分离，最关键的一条】** 同一结论，其**法律层面**（有理性 / 该要件在法律上是否成立）
与**证据层面**（证明前景 / 该事实证得出吗）**必须分别评级、分别标注**，绝不合成一个模糊分数。
—— 这是关联分析法"法律审查先于事实审查"（`00-method` §3.3）在诚实纪律上的落点：一个案子完全可能
**法律层面高置信（诉请在法律上站得住）、证据层面低置信（关键事实证不出）**，二者不可互相稀释。

置信度四级：

- **高** —— 法律层面：有已核验的请求权基础 / 规范支撑，要件与举证分配清楚，五案型分诊已定论；
  证据层面：负客观证明责任方现有证据足以达该要件证明标准，且对手难以拉回真伪不明。
- **中** —— 有据但存在**可补的缺口**或**类案分歧**：要件成立但关键证据待补、或裁判口径有分布不一致、
  或对手有相当机会将本证搅回真伪不明。
- **低** —— 材料薄、要件事实主张 / 证据大面积待补、或结论主要靠模型对罕见案由的**实时推导兜底**。
  低置信结论**只给方向，不下断言**。
- **待核验** —— 结论依赖某个**尚未核验的条号 / 案号 / 事实**。在被核验之前，该结论**不得作为最终依据输出**，
  只作"方向 + 待核验"呈现（见 §3 核验标签）。

**【规则】** 置信度随**材料成熟度**与**核验状态**动态变化，不是固定标签；材料越薄，第二层（证据）置信度
天然越低，须显性标注"此为法律层面预判，证据层面待补"。**分级不拒跑**：低置信不等于不产出，等于诚实降级。

## 3. 溯源：核验标签体系（绝不编造条号案号）

**【规则】每一条法条 / 司法解释 / 案号援引，都带核验标签。无例外。** 承 `claim-basis-table.md` §0：

- `[✓核验 YYYY-MM-DD]` —— 已于该日对照一手 / 权威来源确认。可作最终依据。
- `【待核验】` —— 出自模型知识，**尚未确认**。在被输出**依赖之前**，须由缪或经检索核验；
  未核验前**只给方向**（"查建工司法解释一关于利息计付的条文"），**绝不给伪造的精确援引**。
- `[数据库·须核验]` —— 由已连接的法律数据库 MCP 返回。比模型记忆可靠，但**仍须向律师展示待其确认**，
  不自动升为 `✓`。

**【规则 · 反幻觉三禁】**（吸收自竞品最强的防幻觉架构，内化为纪律）：
1. **禁编造条号 / 案号** —— 不确定的数字一律 `【待核验】`，转 `retrieval-spec.md` 检索方案给方向。
2. **禁编造学理** —— 引擎只用 `00-method` 已锚定的正源（请求权基础谱系 / 规范说 / 关联分析法），
   不自造"XX 原则""XX 说"充数。
3. **禁补事实** —— 当事人没说的事实不替他说；缺主张就标"主张缺口"（第一层检出项），不脑补圆场。

**【规则 · 类案溯源】** 每条类案观点带**来源 + 效力层级**（法发〔2020〕24号，见 `retrieval-spec.md` §3）：
① 指导性案例（应当参照）→ ② 最高法典型案例及生效裁判 → ③ 本省高院参考性案例 → ④ 上级及本院生效裁判。
**除指导性案例外，类案仅"校准"预判，绝不冒充确定结论**；我国同案不同判仍存 —— 须**呈现裁判口径的分布
与分歧**，而非单一断言。

## 4. 立场方向标（客观与立场物理分离的执行面）

**【规则】** 前五阶段的每条结论标 **中立（客观）** 或标出**该结论对哪方有利**（原告向 / 被告向）——
但**标出"对谁有利"不等于给打法**。真正的"怎么打"（攻防着力点、诉请设计、检索报告的诉讼用法）
**只在阶段六出**（`stance-playbook.md`）。
- 例：阶段三说"T4 工程款数额的客观证明责任在承包人、现有结算文件不足 → 证明前景存疑【中 · 承包人不利】"
  —— 这是**客观研判带立场方向标**；
- 到阶段六才说"故被告向应主攻结算缺口、申请工程量鉴定拖入真伪不明；原告向须在起诉前补齐竣工结算文件"
  —— 这才是**立场打法**。
二者物理分离，交付时也分区呈现。

## 5. 降级四态（材料 / 数据库不足时，怎样诚实退让而不停机）

**【规则】** 面对"条号核不了 / 数据库没接 / 材料太薄 / 案由罕见"，引擎按下列**四态**降级，
每一态都**有产出**（分级不拒跑），且**每一态都诚实标注降到了哪一级**：

| 态 | 触发 | 处理 | 出厂置信度 |
|---|---|---|---|
| **T1 已核验** | 条号已 `✓核验` / 数据库返回经确认 | 作最终依据 | 高（法律层面） |
| **T2 数据库待确认** | MCP 返回但未经缪 / 律师确认 | 用，但标 `[数据库·须核验]` + 提示确认 | 中～高 |
| **T3 检索方案** | 无 MCP，或条号 `【待核验】` | 转 `retrieval-spec.md`：给**检索对象 / 类型 / 检索式 / 用途**，**给方向不给伪精确** | 中（方向明确）/ 低（方向存疑） |
| **T4 推导兜底** | 罕见案由，无表可查、无据可核 | 依 `00-method` 学理**实时推导**，全程显性标 `低 · 推导` | 低 |

**【规则】** 降级**只降精确度，不降结构**：无论降到哪一态，请求权基础群、要件清单、两层审查、
决定性要件识别的**框架照常跑完** —— 缺的是某些叶子节点的精确条号 / 现成证据，不是分析骨架。

## 6. 真伪不明与"预判"语气（诚实的语言学落点）

**【规则 · 语气】** 律师版一切结论是**概率 / 区间的预判**，不是判决。语言上：
- **不写**"本院认为……认定如下"（那是判决模拟器的翻车句式）；
- **写**"该要件证成前景较高 / 存疑 / 低""预判法官倾向……""结果最可能落在……区间，最坏情形为……"。

**【规则 · 真伪不明标准句】** 当某争议要件"负客观证明责任方现有证据未达证明标准、且难以补强"时，
标准表述为：**"该要件事实若维持真伪不明，由负客观证明责任的【某方】就此承担不利后果。"**
—— 这是引擎最锋利的预判句式（`00-method` §1.6），不得软化成"可能有点风险"。

---

## 7. 三标如何落到交付面（保持干净，不做学理自白）

**【规则】** 三标在交付物里以**紧凑标记**呈现，**不是学术脚注**：
- 交付面示例：`工程款数额（T4）— 证明前景存疑【中 · 结算文件不足 · 承包人不利】`。
- **绝不**在交付面写"依 Rosenberg 规范说，该要件为权利发生规范，故……" —— 学理是引擎的内脏，
  不是给律师看的说明书（`00-method` §6）。交付面只见**判断 + 置信度 + 一句话根据 + 对谁有利**。
- 客户摘要（`deliverable-client.md`）进一步去术语、去条号细节，只留结论区间 + 最坏情形 + 免责。

## 8. 本文件不是什么

- **不做法律判断** —— 怎么分要件、怎么分配举证责任在 `engine/`；本文件只管怎么**标注**那些判断的可信度。
- **不实现检索** —— 检索式、数据库接口、四层降级的**执行**在 `retrieval-spec.md`；本文件只定**溯源与置信规则**。
- **不放立场打法** —— 只定"立场方向标"这个标签规则；怎么打在阶段六。
