# 检索接口 · 厂商中立 · 四层降级

> 本文件把引擎对"外部知识"的需求，抽象成一个**厂商中立的检索接口**。引擎在推理中会遇到两类它
> 无法凭记忆可靠回答的问题——**某条规范的准确条号 / 现行有效性**，与**类案的裁判倾向**。本文件规定
> 引擎如何把这些需求表达成**检索请求**，如何在**接了 / 没接**法律数据库时都产出可用结果。
>
> **核心承诺**："**接上更强，不接不塌。**" 接上 MCP（元典 / 北大法宝 / 威科 / Alpha / 法信…任一）
> 则自动溯源核验；没接则降级为一份干净的**F-检索方案**交付物——告诉律师**该查什么**，
> 而**绝不编造条号案号**假装查过了。本文件常驻生效于每一阶段。

---

## 0. 阅读约定

- 凡须**执行**的标 **【规则】**；凡属**背景论证**标 *（理据）*。
- 本文件定**检索的接口与降级**；置信度与溯源标签的**规则**在 `epistemics.md`；本文件与之配套使用。

---

## 1. 两类检索对象（引擎只有这两种外部知识需求）

**【规则】** 引擎发出的检索请求，只有两类对象，分别服务不同目的：

| 对象 | 服务于 | 典型问题 | 产出 |
|---|---|---|---|
| **① 规范检索**（法条 / 司法解释） | 找法（阶段二）+ 核验 | "工程款利息计付的准确条号？""建工司法解释一是否现行有效？" | 条号 + 现行效力 + 规范类型 |
| **② 类案检索**（生效裁判文书） | 裁判倾向（阶段四） | "结算缺失时工程款举证责任的裁判口径？" | 类案观点 + 来源 + **效力层级** + 分歧分布 |

*（理据）* 两类对象的**评价标准完全不同**：规范检索求"准"（条号对不对、有没有失效），
类案检索求"倾向与分歧"（多数怎么判、有没有反例）。混为一谈会既错用效力等级、又误判裁判倾向。

---

## 2. 厂商中立接口（不绑任何一家数据库）

**【规则】** 引擎发出的是**抽象检索请求**，不含任何厂商专有语法。适配层（MCP）负责把抽象请求翻译成
具体数据库的调用。**引擎不得假设某一家数据库存在，也不得绑定其字段名 / 检索式方言。**

**抽象检索请求 schema（引擎产出，适配层消费）：**

```
检索请求 {
  对象:   规范 | 类案
  意图:   找法（发现新条文） | 核验（确认已有条号/效力） | 裁判倾向（校准预判）
  关键词: [争点导向关键词，见 §4]      # 案由 + 争议焦点 + 法律适用问题
  规范类别: 主要规范 | 防御规范 | 辅助规范   # 仅规范检索；防止把防御规范当请求权基础
  层级要求: [见 §3，仅类案检索]
  时间窗:  [除指导性案例外，优先近三年]
  用途:   本条检索服务于哪个要件 / 哪个决定性问题
  优先级: 高 | 中 | 低                # 决定性要件相关者置高
}
```

**【规则】** 适配层可对接任一厂商（元典 / 北大法宝 / 威科先行 / Alpha / 法信 等），或不对接。
引擎的行为**不因厂商不同而改变**，只因"接没接上"而在 §5 的四层间降级。

---

## 3. 类案检索的效力等级（法发〔2020〕24号，必须遵守的取用次序）

**【规则】** 类案相似性 = **基本事实 × 争议焦点 × 法律适用问题** 三要素判断（不是"案由相同"即类案）。
按官方**效力等级**取用，高级别优先：

1. **指导性案例** —— 最高法发布，**法院应当参照**（近强制；作裁判理由，不作裁判依据）。**不受近三年限制。**
2. **最高法典型案例及最高法生效裁判** —— 强参考。
3. **本省高院参考性案例** —— 中参考。
4. **上一级法院及本院生效裁判** —— 弱参考，但贴近本地口径。

**【规则】** 除指导性案例外，**优先近三年**（口径与法律适用更新）。

**【规则 · 纪律】** 类案只作**校准**，不冒充结论；同案不同判仍存，须**呈现分布与分歧**，
每条带来源 + 层级标注（`epistemics.md` §3）。**绝不编造案号** —— 无则给检索方向。
*（诉讼机会标记，供阶段六取用，本文件只标不展开）*：律师主动提交**指导性案例检索报告**，
可倒逼法院在裁判文书说理中回应——是阶段六的立场武器，不是本层的检索动作。

---

## 4. 分档检索式（从宽到窄，争点导向）

**【规则】** 检索式**争点导向**（不是把案由名塞进去了事），并**分档**给出——先宽后窄，便于律师按命中率收放。
承 `claim-basis-table.md` 各案由 §"类案检索要点"字段。以建设工程（工程款）为例：

- **宽档**（先框范围）：`建设工程施工合同 工程款 举证责任`
- **中档**（叠加争议焦点）：`建设工程 工程款 竣工结算 工程量 举证责任`
- **窄档**（锁定决定性要件 / 特殊情形）：
  - 数额争点：`工程款 结算 工程量 鉴定 真伪不明`
  - 质量抗辩：`工程质量不合格 工程款 扣减 鉴定 举证责任`
  - 无效情形：`施工合同无效 验收合格 折价补偿 793`
  - 优先受偿权：`建设工程价款优先受偿权 18个月 除斥期间 起算 抵押权 顺位`
  - 实际施工人：`实际施工人 突破合同相对性 发包人 欠付范围`

**【规则】** 检索式**跟着决定性要件走**：§1 请求的"优先级"字段为高者（即决定性要件相关），
优先生成窄档检索式；边缘问题给宽档即可。

---

## 5. 四层降级（接没接数据库，都有产出且诚实标级）

**【规则】** 与 `epistemics.md` §5 的降级四态**一一对应**，此处给检索侧的具体动作：

| 层 | 场景 | 检索侧动作 | 出厂标签 |
|---|---|---|---|
| **T1** | MCP 接上 + 返回经确认 | 直接取用条号 / 类案，作最终依据 | `[✓核验]` / 高 |
| **T2** | MCP 接上但未经缪 / 律师确认 | 取用但标 `[数据库·须核验]`，附原始出处待确认 | 中～高 |
| **T3** | **无 MCP，或条号 `【待核验】`（默认态）** | **产出 F-检索方案**（见 §6）：给检索对象 / 类型 / 分档检索式 / 规范类别 / 用途 / 优先级——**给方向，绝不编条号案号** | 中（方向明确）/ 低 |
| **T4** | 罕见案由，无表可查、无据可核 | 依 `00-method` 学理**实时推导**请求权基础与要件，全程标 `低 · 推导`，并生成 T3 检索方案兜底 | 低 · 推导 |

**【规则】** T3 是**默认交付态**——多数律师不接数据库，引擎的常态就是交一份**能直接拿去数据库照着查**的
检索方案。这份方案本身就是有价值的交付物，不是"没查到"的道歉。

---

## 6. F-检索方案（交付物格式）

**【规则】** 无法即时核验时，引擎产出一份结构化**检索方案**，每一检索项含六要素：

```
检索项 {
  对象:   规范 | 类案
  检索式:  [分档：宽 / 中 / 窄]
  规范类别: 主要 / 防御 / 辅助      # 规范检索项须标，防误当请求权基础
  层级/时间窗: [类案检索项须标效力等级 + 近三年]
  用途:   服务于哪个要件 / 哪个决定性问题 / 补哪个缺口
  优先级: 高 | 中 | 低            # 决定性要件相关置高，律师先查
}
```

**【规则】** 检索方案**与办案清单（阶段五）合流**：`02`/`03` 产出的**证明缺口**（哪个要件证据不足、
需取证 / 鉴定 / 书证提出命令），连同规范 / 类案检索项，一并汇入阶段五的行动清单，按优先级排序交律师。

**【规则 · 交付语气】** 检索方案给的是"**去查什么、怎么查、为什么查、先查哪个**"，
**不是**"我查到了 XX 条"（未核验时）。伪精确比留白更危险——这是我们与翻车工具的分界。

---

## 7. 本文件不是什么

- **不做法律判断** —— 该查什么由 `engine/` 的找法与两层审查决定；本文件只定**怎么把需求表达成检索、怎么降级**。
- **不定置信规则** —— 置信度分层与核验标签的**规则**在 `epistemics.md`；本文件是其**检索侧的执行**。
- **不实现某一家数据库** —— 只定厂商中立接口；具体 MCP 适配是工程实现，随装随用。
- **不放立场打法** —— "提交指导性案例检索报告倒逼法官回应"这类诉讼用法只标记、不展开，属阶段六。
