# 06 阶段 · 立场攻防（打法）

> 这是六阶段动线的**终点**，也是全 skill **唯一出立场的地方**。前五阶段是中立的客观研判（禁立场）；
> 到这一阶段，引擎才翻转为代理人立场，把前面的客观产出 —— 决定性要件、证明前景、对手动作、结果区间 ——
> 转成**可选的打法与建议**。
>
> **本文件不新做法律判断**：请求权基础、要件、证明前景、结果区间都在引擎里定完了，这里只做"知道了这些，
> 该怎么打"。它对全部给付之诉案由通用，**正文一律不出现具体案由的举例**（举例只用抽象的"请求权基础 A /
> 要件 X"），具体案由只是引擎下游数据的打样，不进本文件。

---

## 1. 两条铁律（先立）

**【规则 · 物理分离但可追溯】** 立场只在本阶段出；且**每一条打法都必须回引它的客观根据** —— 哪个决定性
要件、哪段证明前景、对手哪个动作、哪档结果区间。打法一旦脱离研判、凭空生长，就成了纯辩护词，背叛了
引擎。格式见 §6：每条打法条目强制带 `〔根据：…〕`。

**【规则 · 打法是建议，不是命令】** 本阶段交出的是**供律师权衡的选项与建议**，不是指令。最终打哪条、
诉不诉、和不和，由律师与当事人定。引擎给"有哪些打法、各自的代价与前景"，不替律师拍板 —— 尤其成本收益
（§3 打法六）只作建议。

---

## 2. 打法怎么组织

**【规则 · 统领于决定性要件排序】** 六类打法**不是并列罗列、也不是顺序步骤**，而是**统一围绕 `engine/02`
交来的决定性要件排序（胜负手清单）展开**：打法优先服务于排在最前的决定性要件 —— **原告向先补强它、
被告向先攻它**。脱离决定性要件排序的打法是无的放矢。各类打法之间可互相援引（如诉请设计要参考成本收益），
不分先后。

**【规则 · 立场双向读数】** 立场参数（原告向 / 被告向，承接接案卡轴一）翻转每一类打法的读数方向。
打法按类型组织，每类给原告向、被告向两套读数（省重复、与引擎的立场读数一致）。**但两向并不完全对称** ——
有些打法是一方特有（诉请设计只属原告、反诉与管辖异议只属被告），这些在 §5 单独列出，不强行镜像。

---

## 3. 六类打法

> 每类的写法固定为：**目的 → 消费引擎哪个产出 → 原告向 → 被告向 → 可追溯根据**。

### 打法一 · 诉请设计（原告向）/ 应诉设计（被告向）〔N6〕

- **消费**：请求权基础群 + 竞合标注（`engine/01`）、决定性要件排序（`engine/02`）、定性风险（`engine/01` §2.3）、结果区间（`engine/03`）。
- **原告向 · 诉请设计**：
  - **竞合下选主打 + 备位**。请求权竞合**无择一义务，数基础均可为裁判理由**，故不是"选一个"，是"主打最强、
    其余备位同列"。选主打的维度：**诉讼时效长短 · 举证难易（哪个基础的要件我方证得动）· 可主张范围
    （不同请求权基础的赔偿 / 给付口径可能不同）· 管辖（不同基础可能牵动不同管辖）**。
  - **一并主张从权利**：承接接案卡"诉请充分性"的前向引用（从权利、孳息、违约金等），找法确定后回填。
  - **诉请范围取舍**：据结果区间与成本（打法六），决定全额主张、部分主张，还是分案。
  - **规避定性风险**：若"定性被否"风险高（`engine/01` §2.3），预设备位法律关系 / 备位诉请，或调整主张顺序，
    避免"定性一错、赢面归零"。
- **被告向 · 应诉设计**：无诉请可设计，转为 —— 针对原告**主打基础的最脆要件**（决定性要件、且客观证明责任
  在原告者）集中防御；评估是否**争法律关系定性**逼原告落入定性风险；反诉另走打法五。
- **〔根据〕** 主打 / 备位的选择须写明依据哪条决定性要件的证明前景与哪项竞合标注。

### 打法二 · 证据组织与举证策略〔N7 · 攻防部署（打法二~五）〕

> （阶段五已把取证 / 书证提出命令 / 鉴定作为**中立行动清单**列出；本打法是把这些中立选项**立场化部署** ——
> 同一件事，阶段五问"该取什么证"，这里问"怎么用它攻 / 守"。）

- **消费**：决定性要件排序 + 各要件证明前景 + 修正因素（自认 / 书证提出命令 / 鉴定 / 本证反证不对称，`engine/02` §5）。
- **原告向**：围绕**客观证明责任在我方**的决定性要件组织本证达**高度盖然性**；补强易被搅浑的本证；
  主动申请**书证提出命令**（关键书证在对方控制下且属法定应交情形 → 对方无正当理由拒交可推定我方主张为真、
  毁证可推定待证事实为真）；专业事项评估**鉴定**的启动主体与倾向；促成对方**自认 / 拟制自认**。
- **被告向**：善用**本证 / 反证不对称** —— 不必把相反事实证到高度盖然性，**只需把原告本证搅回真伪不明**，
  即可使原告在该要件败诉（被告端天然优势）；优先攻原告**主张缺口**（第一层一击，无须证据）；同时**防己方
  陷入拟制自认**（经询问不表态视为自认）。
- **〔根据〕** 每项举证动作须挂到具体决定性要件及其证明前景缺口。

### 打法三 · 抗辩(权)的行使（被告向）/ 预先化解（原告向）

> 时效"该不该查、届没届满"由 §4 安全条强制核查；本打法只管"查出问题后怎么打"。

- **消费**：抗辩(权)群 + 二分（依职权 / 须主张，`engine/01` §3）、对手动作清单（`engine/03`）、§4 安全条结论。
- **被告向 · 行使**：
  - **抗辩（依职权审）** —— 法院无论如何都审，组织好构成要件事实即可。
  - **抗辩权（须主张）** —— **必须主动、有效行使，且须一审提出**；按效果分级（永久 / 暂时 / 限制性）定优先级。
  - 若 §4 安全条查出**时效 / 除斥期间可主张**：这是被告端可能致命的一手（永久性抗辩权成立即无理由驳回）。
    但**提不提、何时提、如何表述是律师的判断项** —— 提时效可能影响法官心证与调解空间，引擎给规则与权衡点，
    不替律师决定。
- **原告向 · 预先化解**：依职权必审的抗辩（权利妨碍 / 消灭）须在起诉与举证中**预先化解**；若 §4 安全条提示
  我方债权时效存疑，起诉前补**时效中断**证据（催款、对账、部分履行等）。
- **〔根据〕** 每项抗辩(权)须标其二分性质与效果分级，并回引 §4 安全条的时效核查结论。

### 打法四 · 类案检索报告的诉讼用法

- **消费**：裁判倾向 + 类案（带效力层级，`engine/03` §3；检索由 `retrieval-spec.md` 承担）。
- **双向共用**：主动向法院提交**指导性案例检索报告** —— 指导性案例法院**应当参照**，且**应当在裁判文书
  说理中回应**，是把类案变成诉讼武器的正当途径。
  - **原告向**：提交支持我方诉请 / 定性的指导性案例与近三年同口径类案，倒逼法官回应。
  - **被告向**：提交支持我方抗辩 / 相反裁判口径的类案；或指出原告所援引类案**不相似**（基本事实 × 争议焦点
    × 法律适用三要素不符）。
- **纪律**：类案**只校准不冒充结论**，须呈现口径分歧、带来源 + 层级；**绝不编造案号**（接 `epistemics.md`）。
- **〔根据〕** 每条援引须标效力层级与相似度三要素。

### 打法五 · 程序动作

- **消费**：程序站结论（管辖 / 主体适格 / 重复起诉 / 既判力，`engine/02` §2）、对手程序动作预判（`engine/03` §1）。
- **被告向（多为被告特有）**：**管辖异议**（须在答辩期内提，逾期视为接受）、主体适格抗辩、**反诉**（独立之诉 →
  单走一套五轴与立场读数）、追加当事人、**重复起诉 / 既判力（一事不再理）**主张。
- **原告向**：预判对方会提的程序动作（管辖异议等）→ 预先防御（选好管辖、备齐主体适格证据）；主体链
  （名实不符 / 权利承受等疑点，接接案卡主体旗标）→ 决定**告谁**、是否**突破合同相对性**向真正的责任人主张。
  原告没有"反诉"，其对应物是**另案起诉**或**依法扩张 / 变更诉请**，二者与反诉不同，不可混为一谈。
- **〔根据〕** 每项程序动作须挂到程序站的对应结论或主体疑点旗标。

### 打法六 · 成本收益〔N9 · 定性建议，不给数字〕

- **消费**：结果区间 + 最坏情形（`engine/03` §4）。
- **做法**：把结果区间（全部支持 / 部分支持 / 驳回 / 裁定驳回起诉的可能）与**成本要素**并排权衡 ——
  成本要素含：**诉讼费 · 律师费 · 时间 · 执行风险**。据此给出**诉 / 调 / 撤 / 和解**的**建议**（含对调解 /
  和解空间的评估 —— 调解是替代方案，不计入成本要素本身）。
- **双时态**：前瞻（要不要起诉、如何起诉）；回溯（要不要上诉 / 再审 —— 改判前景 × 上诉成本）。
- **纪律（务必守）**：**只作定性区间，不给伪造数额**（`epistemics.md` 伪精确禁令）；**最坏情形必须显性交代**
  （这是当事人最须知道的一格）；本打法**是建议，不是结论**，最终由律师与当事人定。
- **〔根据〕** 建议须挂到结果区间与最坏情形，成本要素据案件实况列举、不虚构金额。

## 4. 时效与失权的独立安全条（强制核查，跨全案）〔N8〕

**【规则】** 在任何研判里，引擎都须把"**相关权利是否附诉讼时效 / 除斥期间 / 其他行使期限，是否届满，
是否需在一审主张**"作为**独立安全条**核查并显性提示 —— 这一步管"**该不该查、届没届满**"，是打法三行使
策略的前提。
- **被告向**：核查对方债权是否已过时效（可主张时效抗辩，须一审提出，二审才提原则上失权），以及是否存在
  **除斥期间届满致权利消灭 / 失权**的事由。此类失权风险**易被忽略而致命，引擎每次都提醒、不默认律师已想到**。
- **原告向（镜像）**：核查己方权利的时效 / 除斥期间，避免主张一个已过期的权利、或漏在期限内行使。
**【规则】** 安全条只做**核查与提醒**，查出的结论交打法三转成行使 / 化解策略；二者分工，不重复。

## 5. 原告向 / 被告向 不对称清单（不强行镜像之处）

- **原告向特有**：诉请设计、竞合主打 / 备位、一并主张从权利、诉请范围取舍。
- **被告向特有**：反诉、管辖异议、应诉答辩集中攻原告最脆要件、拒交 / 毁证的证明妨碍防范。
- **双向对称（各有读数）**：证据组织、类案检索报告用法、成本收益、时效核查（原告预先化解 / 被告行使）、
  程序防御。
- **【规则】** 遇不对称打法，引擎**只出该向可用的那套**，不硬造另一向的镜像 —— 被告没有"诉请设计"，
  原告没有"提反诉"（原告的对应物是"另案起诉"或"扩张 / 变更诉请"，须分辨，不混为一谈）。

## 6. 可追溯纪律的执行格式

**【规则】** 每条打法条目**强制带根据标签**，形如（示例用抽象基础 / 要件，非具体案由）：

```
〔打法〕就诉请甲，主打请求权基础 A、以请求权基础 B 备位。
〔根据〕engine/02 决定性要件排序——基础 A 的关键要件证明前景高于基础 B 的关键要件；
        engine/01 竞合标注——A、B 竞合、无择一义务，二者可同为裁判理由。
〔立场〕原告向。〔置信度〕中（取决于某要件的证据能否补齐）。
```

- 根据须指向**具体的引擎产出**（要件编号 / 证明前景 / 对手动作 / 结果区间），不是泛泛的"综合判断"。
- 三标（置信度 · 来源 · 立场方向）随打法一并出（`epistemics.md`）。
- 追溯不到客观根据的"打法"，是纯辩护词，**不得进交付物**。

## 7. 产出与交接（→ deliverable-lawyer / deliverable-client）

交出一份**立场打法清单**：
1. **六类打法**的择定结果（每条带根据标签 + 三标）；
2. **时效 / 失权安全条**的核查结论与提醒（被告向必含，原告向镜像）；
3. **不对称打法**已按 §5 只出可用向；
4. **成本收益建议**（定性区间 × 成本要素 → 诉 / 调 / 撤 / 和解，作建议）。

**另出对客交代的立场结论**（非"打法"，是把结论对客打包）→ 交 `deliverable-client.md`：去术语、去条号细节，
只留**赢面区间 + 最坏情形 + 建议动作 + 免责**；**不夸胜、不隐最坏情形**。

其余六阶段的客观产出，连同本阶段打法，由 `deliverable-lawyer.md` 按六阶段动线组装成交付物。

## 8. 本文件不是什么

- **不新做法律判断** —— 请求权基础、要件、证明前景、结果区间都在引擎里定完；这里只出"怎么打"。
- **不是判决模拟** —— 出的是代理人立场的打法与建议，不是中立裁断。
- **不给伪精确** —— 成本收益不编数额、类案不编案号；未核验的标 `【待核验】`。
- **不替律师拍板** —— 打法是选项与建议，诉 / 调 / 撤由律师与当事人定。
- **不含案由专属内容** —— 六类打法与举例对全部给付之诉通用；具体案由只在引擎下游数据里。
