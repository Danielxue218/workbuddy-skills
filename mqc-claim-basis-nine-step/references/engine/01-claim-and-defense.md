# 01 · 找法：请求权基础与抗辩(权)的确定

> 本文件是**找法方法**（体），对应六阶段动线的**阶段二**、九步法的 **①②③④**（搭建三段论大前提）。
> 它承 `00-method.md` 的学理，**调用数据文件** `claim-basis-table.md`（找法的数据）：本文件是方法，方法调数据。
> 本步产出一份贯穿全程的**要件清单**，是 `02`、`03` 一切分析的唯一挂载点。
>
> *（背景）* 九步法缘起于长宁法院对超审限案件的诊断 —— "四个不固定"：诉讼请求、法律条文、
> 证据材料、诉讼主张不固定。律师版研判同理：本阶段的任务，就是先把**诉讼请求、请求权基础、
> 要件**这三样"固定"下来，后两样（证据、事实主张）留待 `02`。

---

## 0. 本文件的位置与产出

- **输入**：阶段一的结构化案情 + 诉讼地位（原告 / 被告）+ 案由线索 + 材料成熟度评级。
- **四道工序**（对应九步 ①②③④）：固定权利请求 → 确定请求权基础 → 确定抗辩(权)基础并二分 → 构成要件分解。
- **产出**：请求权基础群（带规范类型 + 核验标签 + 竞合标注）· 抗辩(权)群（带二分）· **要件清单**（带证明责任种子）·
  **定性风险提示** · 检索方案 · 边界与主体 / 管辖标记。

## 1. 工序一 · 固定权利请求（九步①）

### 1.1 按诉讼请求的类型逐项固定
**【规则】** 不同类型的诉请，固定的要点不同（依邹碧华原著）：
- **请求给付钱款 / 实物** → 明确给付主体、种类、金额、**构成及计算方法**；
- **请求履行行为** → 明确履行内容、方式、**是否便于执行**；
- **请求多被告担责** → 明确各被告责任**性质与份额**（连带 / 按份 / 补充）；
- （请求确认效力 / 确认权属 → 属确认之诉，见 §1.4 边界。）

### 1.2 三种情形的处理
**【规则】**（律师版转译为"研判前的固定"，不含法院释明权）：
- **诉请不明确** → 回阶段一追问，明确其确切含义；
- **诉请不充分**（可能遗漏重要请求）→ 探求当事人真实意思，提示可补的请求（如可一并主张的利息、违约金）；
- **诉请不正确 / 相互矛盾** → 指出并建议更正、剔除矛盾。

### 1.3 立场读数
- **原告向**：把己方诉请固定到"可执行、可涵摄"的程度（金额有计算、责任有性质）。
- **被告向**：审视**对方诉请的固定漏洞**（数额无计算依据、责任性质不清、请求自相矛盾）——这些本身即是攻防点。

## 2. 工序二 · 确定请求权基础（九步②）—— 最重要、也最难的一环

*（理据）* 邹碧华称此为"民事审判中最重要、最难的环节"。因为请求权基础一旦不同，**四样东西全变**：
① 权利义务内容；② 构成要件（诉辩重点）；③ 诉讼时效；④ 证明责任分配。选错基础，后面全盘皆错。

### 2.1 五步找法
**【规则】** 按邹碧华的找法次序操作（接驳层在第 1–2 步之间进入）：
1. **确定诉的类型**（给付 / 确认 / 形成）——非给付之诉触发边界（§1.4 边界守门，见下）；
2. **由诉的类型 + 案由，确定可能的权利类型**（如损害赔偿、价款给付、返还）——**以案由查 `claim-basis-table.md`**
   取得请求权基础群种子；
3. **依权利类型的指引，寻找可能支持的法条**——按 00-method §1.3 检索顺序通盘检索；
4. **结合起诉所依据的基本事实，确定具体的请求权基础**（同一权利类型可能对应数个基础，如"返还"的
   基础可有六七种，须结合事实锁定）。

### 2.2 非封顶、规范类型甄别、竞合处理（承 00-method，精简执行）
**【规则】**
- **非封顶**：案由只是种子，仍跑完整检索顺序、跨法律关系检验竞合 / 聚合（§1.4）。
- **规范类型甄别**：每条命中规范标注类型（主要 / 辅助 / 参引 / 宣导 / 防御）；**防御规范绝不当请求权基础**；
  不完全法条 / 定义性法条不能独立作请求权基础，须与相关条文配合（§1.5）。
- **竞合 / 聚合**：法条竞合择一适用；请求权竞合择一主张、但数基础均为裁判理由（无择一义务）；请求权聚合
  可并列。竞合直接牵动**时效与证明责任的差异**，是诉请设计（阶段六）的关键。

### 2.3【律师版核心转译】预判法官的定性 —— 把法官的三把武器翻转为预判
*（理据）* 法官在本步握有三样律师没有的权力：**释明权**、**依职权认定法律关系**、**法律观点开示义务**
（法官应及时公开其法律观点，避免"诉讼突袭"）。律师无此权力，但**必须把它们全部翻转成预判**，这是
"预判法庭"最前端、也最致命的一环：

**【规则】** 本步必须产出**定性风险提示**：
- **定性被否的风险（最致命）**：我方主张的法律关系 / 请求权基础，法官**未必接受**。若法官认定的法律关系
  与我方不一致：法官会释明是否变更诉请；**拒绝变更的，判决驳回诉请；既不明确又拒绝确认法院认定的，
  裁定驳回起诉**。—— 这意味着**定性一错，后面赢面全部归零**。此风险须在本阶段最先标出。
- **预判法官可能的不同定性**：列出本案除我方主张外，法官可能采的其他定性 / 请求权基础，及其对我方的利弊。
- **预判释明方向**：法官可能释明要求补充、变更、剔除的点（对应 §1.2 的三情形，只是主体换成法官）。

*（这是律师版区别于一切"照搬九步"工具的地方：法官版在此"行使"权力，律师版在此"预判"权力如何落到自己头上。）*

### 2.4 核验纪律
**【规则】** 每条法条 / 司法解释带核验标签（`claim-basis-table.md` §0）；**绝不编造条号 / 案号**；未核验者
标 `【待核验】` + 入检索方案（给方向不给伪精确）。接法律数据库 MCP 则自动核验溯源，未接则降级为检索方案。

## 3. 工序三 · 确定抗辩 / 抗辩权基础并二分（九步③）

### 3.1 答辩审查
**【规则】**（依邹碧华原著操作）：
- 审查对方（或预判对方）答辩是**单纯否认**，还是提出了**具体抗辩 / 抗辩权**；
- 凡涉实体法上的抗辩权，须**找到对应的具体法条**（防御规范基础）；
- 若答辩实为**反诉**，识别并单列（反诉是独立之诉，另行分析）。

### 3.2 否认、抗辩、抗辩权的三分
**【规则】**（此三分决定证明责任，务必分清）：
- **否认** —— 直接否定对方要件事实。**不改变证明责任分配现状**，对方要件事实仍由主张方证。
- **抗辩（Einwendung）** —— 承认对方事实，另主张对抗的法律效果（权利妨碍 / 权利消灭）。**法院依职权审**；
  提出抗辩的一方对该抗辩的**构成要件事实**承担证明责任。
- **抗辩权（Einrede）** —— 拒绝给付的权利（时效 / 同时履行 / 先诉等）。**须当事人主动有效行使**，法院不得
  依职权审、不得释明；提出方对其构成要件事实举证。

### 3.3 二分标注与立场读数
**【规则】** 每一防御事由强制作二分标注（依 00-method §1.7）：**抗辩 → 依职权审 → 无条件预判**；
**抗辩权 → 须主张 → 有条件预判（评估对方是否会提）**。抗辩权再按效果分级（永久 / 暂时 / 限制性）。
- **被告向**：本工序是**主攻线** —— 逆攻防链找原告最脆的要件、与可致命的抗辩(权)。
- **原告向**：本工序用于**预先应对** —— 尤其对依职权必审的抗辩，须在诉状与举证中预先化解。

---

## 4. 工序四 · 构成要件分解（九步④）

### 4.1 请求权检视框架（产生 → 消灭 → 可行使）
**【规则】** 对每一请求权基础，按三层检视框架分解（王泽鉴），此框架恰与规范说四分对应：
1. **请求权已发生** —— 全部**权利发生（积极）要件**满足，且无**权利妨碍**事由；
2. **请求权未消灭** —— 无**权利消灭**事由；
3. **请求权可行使** —— 无**抗辩权**（权利受制）阻却。
积极要件由请求人证；妨碍 / 消灭 / 受制由相对人证（§1.6）。此框架天然把"要件"与"抗辩(权)"分列，避免混淆。

### 4.2 构成要件的分层剖析（显性要件 + 隐含前提要件）
**【规则】**（邹碧华原著的关键操作，以承揽合同为例）：一个请求权基础的要件往往分三个层次 ——
1. **本条显性要件**（如"定作人中途变更 + 承揽人损失 + 因果关系"）；
2. **隐含前提一：法律关系性质**（该合同须是承揽合同 → 涉合同定义性法条）；
3. **隐含前提二：合同成立并生效**（涉要约、承诺、生效要件等）。
分解时须把隐含前提一并列出，否则要件不完全（不完全法条须经解释 / 补充获得完全法条）。

### 4.3 无争议 / 免证要件的"默示满足"规则（连接两层审查的枢纽）
**【规则】** 要件**无须展开证明前景**的情形有二：(1) **各方无异议**（隐含前提以"默示满足"形式存在）；
(2) **法定免证事实**（证据规定第10条：众所周知、法律推定、生效裁判 / 仲裁裁决 / 公证文书确认等，见
00-method §1.6）。二者之外的**有争议要件**才进入第二层证明前景分析。—— 这条规则正是第一层（全要件·
有理性）与第二层（仅争议要件·证明前景）的分流阀：`02` 只对"未默示满足、非免证、存在争议"的要件展开推演。

### 4.4 补充规范常成核心争点
**【规则】** 不完全法条 / 定义性法条往往是基础规范的**补充规范**；实务中，补充规范的构成要件**经常成为
案件的核心争点、关键要件**。分解时对补充规范要件保持同等精细，不可略过。

### 4.5 产出"要件清单"
**【规则】** 输出结构化**要件清单**，每个要件条目含：
- **要件名 + 层次**（显性 / 隐含前提）；
- **类型**（权利发生 / 妨碍 / 消灭 / 受制）；
- **证明责任种子**（发生要件→请求人；妨碍 / 消灭 / 受制→相对人）；
- **证明标准**（默认高度盖然性；欺诈 / 胁迫 / 恶意串通 / 口头遗嘱 / 口头赠与→排除合理怀疑；程序事项→较大可能性）；
- **争议状态初判**（默示满足 / 免证事实 / 有争议待证——供 `02` 分流）；
- **对应待证事实**（该要件需要哪些事实支撑）。

这份要件清单是交给 `02-proof-and-prospect.md` 的**唯一挂载点**。

---

## 5. 材料不充足下的运行

**【规则】** 找法主要在**规范侧**展开，**材料很薄也能跑**：请求权基础、抗辩(权)、要件清单基本可依案由与诉请推定。
材料不足只影响两处，且都不停机：
- **定性缺口**：诉请 / 案由不明到无法定性 → 回阶段一追问（§1.2）。
- **条号缺口**：无法核验的条号 → 标 `【待核验】` + 入检索方案（§2.4），不编造。
定性风险提示（§2.3）在材料越薄时越要显著，因为薄材料下定性出错概率更高。

## 7. 本文件不是什么

- **不做证明前景评估**：能不能证成、证不出谁败，是 `02`；本文件只搭大前提、出要件清单与定性风险。
- **不做结果预判、不推演对手是否会提抗辩**：那是 `03`；本文件只**识别**抗辩(权)基础并二分。
- **不放立场打法**：立场（攻防着力点）只在阶段六产出；本文件的"立场读数"仅指分析方向。
- **不编造条号**：不确定即 `【待核验】` + 检索方案，给方向不给伪精确。
