# 竞品分析 · 四家"九步法/法律 AI"Skill 研究

> 本文件整理本项目对四家同类 / 相邻 skill 的研究结论，供设计与验真参考。
> 原则：**公允记功，再下判词**。每家先给它做对的、值得学的，再指出它的天花板。
> 结论先行：**四家都挂着"九步"的招牌，但无一有真正的引擎。** 它们的差别在体裁与工程成熟度，
> 共同的短板在**法学教义的深度**与**受众定位**。这正是本项目的机会。
> 最后更新：2026-07-07

---

## 0. 一句话总判

| 竞品 | 体裁 | 工程成熟度 | 致命短板 |
|---|---|---|---|
| 深圳分所 legal-sz-hk-trial | 深港跨境审理工具 | ★★★★（最高） | scope 蔓延 + 为比赛优化，受众与场景发散 |
| 杨泉辉 判决书生成器 v4.0 | 判决书生成器 | ★★★（次高） | **受众错位**：判决器给律师；单方起诉状→"原告全胜"翻车；扔掉规范说 |
| 潘淑艳 律师办案工作流 | 律师工作流 | ★★ | 右定位（对味）但理论浅，无引擎 |
| 赵璇 邹碧华 persona | 人物复刻 | ★ | 复刻的是"邹碧华其人"，不是"他的方法"；40% 司改 noise |

**共同结论：四家都有"九步的标题"，无一有"九步的引擎"** —— 缺检索顺序、缺规范说举证分配、缺抗辩三分、
缺关联分析法两层审查、更无程序站 / 主文站。工程成熟度排序：深圳 > 杨 > 潘 > 赵；**受众全部错位或发散**。

## 1. 杨泉辉 · 判决书生成器 v4.0（工程最扎实的一家，也最值得剖）

**值得记的功（真本事，不吝褒奖）：**
- **防幻觉架构是四家最强**：六条铁律（禁补事实 / 禁和稀泥 / 禁跳步 / 禁旧法 / 禁编造理论 / 必须回应抗辩）+
  三层法条管控（时效性 / 序号内容匹配 / 理论真实性）+ "真伪不明"标准句。
- **"证据距离原则"这类护栏**：他们发现 AI 会自造学理，于是加了防线 —— 正是"风险分级"承诺的兑现。
- **材料预处理**：把"缺哪些材料"映射到降级步骤，四家里只有他有，很聪明。
- **诉讼细节到位**：诉请依赖关系、联动驳回处理得细；**否认 vs 抗辩**的区分是四家里落地最具体的（带举证责任后果）。
- **"八个一致"质检锁** + 自审 + 警示旗，把质量闸做得最接近其宣传承诺。
- **涵摄表（要件→小前提→归入结论）** 是三段论逻辑最清晰的实现。

**它的天花板（也最致命）：**
- **受众根本错了**：这是把 AI 设计成"扮演法官写判决"，可它通过律师的公众号 / 开源分发 —— **法官不会从律师
  公众号装它，装它的是律师，而律师拿到的是一份"给自己案子判决"的东西**。这更像"看 AI 模拟判决"的猎奇，
  不是办案工具。律师需要的是**站在代理人立场论辩**，不是采纳法官中立裁断的姿态。
- **单方输入→全胜翻车**：仅凭原告起诉状，就生成"本院认为…判决如下"支持原告全部诉请。**有司法中立的外观，
  却只读了一方的故事** —— 质检把未经质证的原告主张当"正确"放行。
- **扔掉了规范说**：为"禁用外国理论"，只用"谁主张谁举证 + 积极抗辩由抗辩方举证"，**没有把要件映射到
  权利发生 / 妨碍 / 消灭 / 受制 去推导举证分配**。讽刺的是，民诉法解释第91条本身正建立在规范说上 ——
  拒用"外国理论"等于扔掉了91条底下的引擎。
- **抗辩三分（妨碍/消灭/受制）与抗辩 vs 抗辩权**：列了，但没有真正操作化。
- **检索顺序缺失**：demo 撞上"商品房预售"这种单一基础明显的案子才没露馅；真遇请求权竞合，没有排序方法。

**给本项目的启示**：他的防幻觉纪律与材料预处理值得吸收（我们已内化为核验纪律、分级不拒跑）；但**受众必须
翻转** —— 我们做的是律师的对抗性预判工具，不是判决模拟器。他"单方→全胜"的病根，正是缺**程序站与被告站**
（本项目已用 02 第零层程序站 + 被告站补上）。

## 2. 深圳分所 · legal-sz-hk-trial（工程最成熟，但发散）

**值得记的功：**
- **工程成熟度四家第一**：Docker + docker-compose + 多 MCP + install.sh + test.sh + CHANGELOG，
  自建 154 条 HK 判例库、HKLII 检索脚本，深港跨境场景做得扎实、可部署。
- 跨境（arbitration / cross-border transfer / HK due diligence）的领域文件成体系，worked example 完整。

**它的天花板：**
- **scope 蔓延**：深港跨境审理 + 仲裁 + 尽调 + 判例库，摊得很大，"极度垂直"的反面。
- **为比赛 / 展示优化**（contest-optimized），受众与真实办案动线发散，重工程轻教义。
- 同样**没有请求权基础引擎**：判例库丰富，但缺"检索顺序 + 规范说举证分配 + 两层审查"的方法内核。

**给本项目的启示**：工程可插拔、MCP 降级是对的方向（我们已定"厂商中立 + 不接不塌"）；但**要极度垂直**，
不摊大饼 —— 我们只做给付之诉的律师预判，深度换广度。

## 3. 潘淑艳 · 律师办案工作流（定位对味，但浅）

**值得记的功：**
- **受众与场景定位是四家里最"对味"的**：面向律师办案工作流，接 MCP，右定位（不像杨那样受众错位）。
- 工作流动线的意识在，知道律师要的是"办案"不是"判决"。

**它的天花板：**
- **理论浅**：有工作流的壳，无请求权基础 / 规范说 / 关联分析法的里子。步骤是"做什么"的清单，
  不是"为什么这么判"的引擎。
- 无检索顺序、无举证分配推导、无两层审查。

**给本项目的启示**：它证明了"律师办案"这个受众定位是对的；我们要在**同样对味的定位上，补上它缺的引擎**。

## 4. 赵璇 · 邹碧华 persona 复刻（研究纪律好，但复刻错了对象）

**值得记的功：**
- **研究纪律扎实**：writings / conversations / expression-dna / external-views / decisions / timeline 六件套，
  人物资料的采集与结构化做得规整。
- **"八个一致"质检**思路好（与杨的质检锁异曲同工）。

**它的天花板：**
- **复刻的是"邹碧华其人"，不是"他的方法"**：persona 还原了他的表达风格、生平、观点，
  却没有把**要件审判九步法这套方法**做成可运行的引擎。
- **约 40% 是司改 noise**：大量内容是司法改革、人物纪念，与"办案方法"无关。
- 受众是"想跟邹碧华聊天"，不是"想用他的方法办案"。

**给本项目的启示**：方法 ≠ 人物。我们要的是**把邹碧华的方法做成引擎**，且溯到他方法背后的正源
（请求权基础、规范说、关联分析法），而不是复刻他这个人。研究纪律（分文件、结构化）值得学。

## 5. 综合判词与本项目的差异化

**四家的共同盲区（= 本项目的立身之本）：**
1. **无检索顺序** —— 找请求权基础全凭运气或案由直查，遇竞合就抓瞎。
2. **无规范说举证分配** —— 不把要件映射到权利发生 / 妨碍 / 消灭 / 受制，举证责任只会喊"谁主张谁举证"。
3. **无抗辩三分与抗辩 vs 抗辩权的操作化** —— 列了名词，不会用。
4. **无关联分析法两层审查** —— 不区分法律审查（有理性）与事实审查（证明前景），更无程序站 / 主文站。
5. **受众错位或发散** —— 判决器给律师、persona 给粉丝、跨境工具摊大饼。

**本项目的定位（对症）：**
- **受众钉死**：已接案的律师，冷推演诉讼（原告 / 被告双向）。
- **引擎坐正源**：请求权基础谱系（Windscheid→Larenz→Medicus→王泽鉴）+ Rosenberg 规范说 +
  Relationstechnik 正源六站（程序站→原告站→被告站→反/再抗辩→证据站→主文站）+ 律师版 Anwaltsrelation。
- **场景化跨越**：把每一站从"审查已作陈述"改造成"预判未上桌的对手与法官" —— 这一步四家都没有。
- **极度垂直**：只做给付之诉预判，深度换广度，不摊大饼。
- **防翻车**：程序站（预判裁定驳回起诉）+ 被告站，从机制上堵死"单方材料→全胜"（杨的病根）。

**一句话**：四家有"九步的标题"，我们做"九步的引擎"，而且是坐在德国正源上、恢复了正源自己的律师视角、
再为中国律师的判决前预判场景做了改造的引擎。
